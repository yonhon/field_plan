# field_plan

いのーファームの圃場の計画と管理を、ブラウザーで行うアプリです。
計画は PC で作り、作業内容はスマホで確認します。見られるのはログインした本人だけです。

## 1. 考え方

計画は、実際の作業の順に、次の 4 つの入れ物で持ちます。

| 入れ物 | 内容 |
|---|---|
| 有効圃場 | 耕してよい場所。物置、井戸、通路を除いた範囲 |
| 耕起対象区画 | 有効圃場を線で分けたもの。**畝立ての前まで**の作業（心土破砕、ロータリー、太陽熱消毒、緑肥など）を区画ごとに計画する |
| 畝 | 区画の中に置く四角形。前後と左右の隙間が通路になる |
| 作付 | 1 本の畝で、**畝立てから収穫まで**の 1 回ぶん。品目と作業（畝立て、マルチ張り、定植・播種、収穫、残渣処理）を持つ |

時間の決まりは次のとおりです。

- 畝には、前の作付の収穫完了予定日のあとに、次の作付を置けます。回転の速い品目は、同じ畝に作付が 2 つ、3 つと並びます。
- 収穫完了予定日より後の日付で、畝をなくせます。
- 畝のない場所は、その日付から新しい耕起対象区画に設定し直せます。前の日付を表示すれば、前の区画と畝が見えます。

### 作る順番

1. 圃場と区域の作図（済み）
2. 耕起対象区画、畝、作付と、その作業の計画（済み）
3. 日程の逆算と警告（済み）
4. 品目の設定値からの苗数、施肥量の計算（済み）
5. 作業の実績（実績と管理作業の計画の入力、計画とのつながりまで作った。[計画](docs/actuals-plan.md)）

### 計算式

| 項目 | 式 |
|---|---|
| 苗数 | 切り捨て（畝長 ÷ 株間）× 条数 |
| 畝の面積 | 畝長 × 畝幅 |
| 窒素量 | 畝の面積 × 10 a あたりの窒素量 ÷ 1,000 ㎡ |
| 肥料の量 | 窒素量 ÷ 肥料の窒素成分（%） |

`agri_db`、`inoo_farm` と同じく、ビルドのない静的な HTML/JS と Supabase で作ります。
Supabase のプロジェクトは共用で（プロジェクト参照 ID: `byhthaiwbutqstrqbwwc`）、このアプリのテーブルは `field` スキーマに置きます。

### テーブル

```
fields（圃場。active_plan_id で実際に使うプランを指す）
├─ backdrops（下絵の位置合わせ）
├─ work_logs（作業の記録。プランではなく圃場に付ける）
│  ├─ work_log_targets（対象の畝・区画と、つながる計画の作業）
│  └─ work_log_inputs（使った資材）
└─ plans（プラン）
   └─ zones（区域。有効圃場、物置、井戸、通路など）
      └─ blocks（耕起対象区画。始まる日となくなる日を持つ）
         ├─ works（畝立ての前までの作業）
         └─ beds（畝。なくなる日を持つ）
            └─ plantings（作付）
               └─ works（畝立てから後の作業）

work_types（作業の種類と目安の日数。plannable が false の種類は記録だけに使う）、crops（品目の設定値）、fertilizers（肥料）、
dev_notes（開発日誌のメモ）は、すべての圃場で共通

weather_daily（アメダスの観測所ごとの日ごとの気温と降水量）、
famic_imports・famic_products・famic_uses（FAMIC の農薬登録情報。画面からは読むだけ）も共通
```

圃場はいくつも持てます。外形、下絵、プランは圃場ごとです。
図形は、圃場の基準点を原点としたメートル座標の多角形で持ちます。
区画、畝、作付、作業はどれもプランの ID を持ち、プランごとにまとめて読み込みます。

## 3. データを守る仕組み

- テーブルは `field` スキーマに置き、RLS で `field.owners` に登録した利用者にだけ読み書きを許します。
- 下絵の画像（集成図など）には地番や氏名が写っていることがあるので、リポジトリに入れず、非公開のストレージ（`field-plan`）に置きます。
- 圃場の場所、面積、作付の予定などは、このリポジトリに書きません。DB にだけ置きます。
- 計画の表の行を足す・変える・消すたびに、DB が変える前と後の行を `field.audit_log` に残します。DB が一緒に消した行（区画を消したときの畝など）も残ります。画面からは読めず、事故を調べたり、消えた行を戻したりするときに、DB に直接つないで読みます。1 年より古い行は、毎日 3:30 に pg_cron が消します。開発日誌のための変更の記録（`field.changes`）とは別のものです。
- 共用の DB 全体を、毎日 2 回（16:23 と 4:23 が目安）バックアップします。暗号化してから Supabase の外の非公開の置き場に送り、直近 8 日、週ごと 35 日、月ごと 370 日のぶんを残します。仕組みと戻し方は、非公開のリポジトリ `shared_db_backup` にあります。下絵の画像はバックアップの対象外です。消えた行を戻すときは、まず `field.audit_log` を見て、それで戻せないときにバックアップを使います。

## 4. 最初の準備

一度だけ行います。

1. Supabase の SQL Editor で `sql/field.sql` を実行します（実行済み）。
2. Integrations > Data API > Settings（または Project Settings > Data API）の Exposed schemas に `field` を加えます。
3. Authentication > Users でログイン用の利用者を作ります。
4. その利用者の ID を登録します。

   ```sql
   insert into field.owners (user_id) values ('利用者の ID');
   ```

5. 2 週間気温予報の関数を配備します（配備済み）。

   ```
   bun x supabase functions deploy field-weather --project-ref byhthaiwbutqstrqbwwc
   ```

6. GitHub Actions が気象の値（毎日、`weather.yml`）と FAMIC の農薬登録情報（週に 1 回、`famic.yml`）を入れるために、取り込み係の利用者を作ります（作成済み）。Supabase Auth に利用者を作って `field.importers` に登録し、そのメールアドレスとパスワードを、GitHub のリポジトリの Settings > Secrets and variables > Actions に `FIELD_IMPORTER_EMAIL`、`FIELD_IMPORTER_PASSWORD` として置きます。取り込み係にできるのは、気象の値と FAMIC の入れ替えだけです。DB の接続文字列は GitHub に置きません。

## 5. 圃場の作図

圃場は、右の「圃場」の欄で切り替えます。「新しい圃場」で圃場を足すと、空のプラン「プラン1」が 1 つ付きます。「圃場を削除」は、開いている圃場を、外形、下絵（画像も）、プランと、その中の区域・区画・畝・日程ごと消します。開発日誌の記録とメモは残ります。圃場が 1 つだけのときは消せません。
外形、下絵とその縮尺・向き、プランは圃場ごとなので、ほかの圃場の図形は変わりません。前に開いていた圃場とプランは、次に開いたときにも開きます。

1. 「下絵と縮尺」で、下絵にする図（集成図や航空写真）の画像を読み込みます。保存の状態の欄に、送った割合が出ます。60 秒のあいだ少しも進まなければ止めて知らせるので、回線を確かめるか、画像を小さくしてから読み込み直してください。
2. 「外形を描く」で圃場の角を順にクリックし、最初の点をクリックして閉じます。
3. 縮尺を合わせます。現地で測るまでは「面積で合わせる」（登記などで分かっている面積を入れる）を使い、測ったあとは「2 点の距離で合わせる」で直します。図形と下絵が一緒に伸び縮みします。あとから下絵を差し替えるときは、下の「下絵を差し替える」を見てください。
4. 区域の種類（有効圃場、物置、井戸、通路、残渣処理場、その他）を選び、次のどれかで描きます。
   - **多角形**: 角を順にクリックします。
   - **四角形**: 対角の 2 点をドラッグします。
   - **寸法を指定**: 辺に沿う長さと奥行きを入れ、置く場所をクリックします。

四角形は、いちばん近い外形の辺に平行になります。変更は自動で保存されます。スマホの幅では閲覧だけになります。

図形を選ぶと、それを囲んでいる図形の各辺と、近くの図形までの距離が出ます（区域は外形とほかの区域、区画は有効圃場とほかの区画、畝は区画と両隣の畝）。位置を決める方法は 3 つあります。

- 距離の数字をクリックして、その距離を数値で指定する（例: 圃場の端から 2 m）
- 矢印キーで 10 cm ずつ動かす（Shift を押しながらだと 1 m）
- ドラッグで動かす

区域と区画の大きさは、次の方法で変えます。

- 辺の中ほどの丸をドラッグすると、その辺が平行に動きます。
- 辺の長さの数字をクリックすると、長さを m で指定できます。辺の始まりの頂点は動かず、終わりの側がずれます。

圃場の外形だけは、辺の中ほどの丸をドラッグすると、そこに頂点が足されます。

有効圃場を動かすと中の区画と畝も、区画を動かすと中の畝も一緒に動きます。

図形は「圃場の外形 ⊇ 区域 ⊇ 耕起対象区画 ⊇ 畝」の順に入っているはずです。入れ物からはみ出した図形は、図では赤い点線になり、圃場図のすぐ上に赤い文字で出ます。文をクリックすると、その図形が選ばれます。上部の「圃場図」のタブには警告の件数が付き、区域と耕起対象区画の一覧でも、はみ出している行に ⚠ が付きます。区画と畝は、表示日にあるものだけを見ます。大きさを変えたときは、中の図形は自動では動かないので、この表示で確かめてください。

外形と下絵は圃場に 1 つで、区域、区画、畝、日程はプランごとに持ちます。プランは新規、コピー、名前の変更、削除ができます。

### 下絵を差し替える

下絵には 2 つの役割があります。「下絵と縮尺」の欄に、いまの下絵がどちらかが出ます。

| 役割 | どんな下絵か | 縮尺・向きを変えると |
|---|---|---|
| 図形を描く下絵 | 図形のない圃場に読み込んだ下絵（ふつうは圃場の最初の 1 枚） | 図形も一緒に伸び縮み・回転する |
| 図形に合わせて置いた下絵 | 図形がすでにある圃場に読み込んだ下絵 | 下絵だけが変わり、図形は変わらない |

図形に合わせて置いた下絵は、次の順に合わせます。

1. **縮尺**: 「2 点の距離で合わせる」で、下絵に描かれた尺度の線の両端など、実際の距離が分かっている 2 点をクリックし、距離を入れます。下絵が、描かれた尺度のとおりの大きさになります。2 点の中ほどは動きません。
2. **位置と向き**: 「図形に位置を合わせる」で、下絵の上の目印（角や杭など）と、それが来るべき図形の上の点を、順にクリックします。下絵が平行移動します。続けて 2 つ目の目印と図形の上の点をクリックすると、向きも合わせます。大きさは変えません。位置だけでよければ、1 組目のあとで Esc を押します。
3. **大きさの食い違い**: 2 組で合わせると、図形と下絵の大きさがどれだけ違うかが出ます（例: 図形は、この下絵の尺度より 2.3% 大きくなっています）。図形のほうが誤っているときは「図形を下絵の縮尺に合わせる」で、この圃場のすべてのプランの図形の大きさを直します。下絵のほうが不正確なら、そのままにします。

「下絵の上と北のずれ」の欄で向きを変えたときも、図形に合わせて置いた下絵では、下絵だけが画面の真ん中のまわりに回ります。
「面積で合わせる」は、図形に合わせて置いた下絵では、外形の面積に合わせて図形の大きさだけを直します（下絵は変わらないので、下絵と図形がずれます）。

**解像度だけを変えた画像**: 前の下絵と縦と横の比が同じ画像を読み込むと、「同じ範囲として引き継ぐ」か尋ねます。引き継ぐと、画素の数の比から、前の下絵の縮尺・位置・向きをそのまま移します。比が 1% より違う画像は、仮の縮尺（1 画素 = 10 cm）で置きます。

## 6. 耕起対象区画と畝

### 表示日

圃場図は、上の「表示日」にある区画と畝だけを描きます。表示日はブラウザーが圃場ごとに覚えていて、次にその圃場を開いたときも同じ日になります（開いていたプランと、工程表の表示も、圃場ごとに覚えます）。区画を作り直すとき、畝をなくすときは、表示日がその日付になります。
最初に作る区画と畝は「最初から」ある扱いで、表示日に関係なく見えます。

### 区画を作る

| 道具 | 使い方 |
|---|---|
| 有効圃場を区画にする | 有効圃場をクリックすると、全体が 1 つの区画になる |
| 線で分ける | 区画（または区画のない有効圃場）の中をクリックし、近いほうの端からの距離を数値で決めて 2 つに分ける。線の向きは、短い辺に平行か、長い辺に平行かを選ぶ |
| 区画を描く | 有効圃場の中で対角の 2 点をドラッグする |

有効圃場の一部だけを耕すときは、線で分けたあと、耕さない区画を削除します。
畝をまたぐ位置では分けられません。区画を分けると、畝は入っている側に付き、区画の作業は両方に同じものが入ります。

### 畝を見る視点

畝の手前と奥、日程の「区画と畝」の図の左右、畝の番号の順は、圃場を見る視点で決まります。
右の一覧で「圃場の外形」を開き、「視点 1」と「視点 2」に、立つ側の辺を選びます。辺は「辺 1 → 2（北東側、12.50 m）」のように出て、図には頂点の番号と、視点の矢印が出ます。

- 畝の長い辺が、視点 1 の見る向きに近ければ視点 1 から、直角に近ければ視点 2 から見ます。視点 2 には、視点 1 と直角の辺を選びます。
- 手前は、その視点に近い側の端です。畝の番号は、その視点から見て左から順です。
- 決めていないときは、図の下（南）からと、図の左（西）から見ます。
- 視点を変えると、畝の番号を振り直します。ほかのプランは、開いたときに振り直します。

### 畝を並べる

畝の追加、移動、削除は、日程の画面の「区画と畝」の図で行います（7 章）。圃場図では、畝は見るだけで、ドラッグや矢印キーでは動きません。畝を選ぶと、右の一覧に幅と長さ、作付が出て、「日程で開く」で日程の画面へ移れます。
区域や区画を削除すると、中の畝も一緒に消えます。

### 畝をなくす、区画を設定し直す

1. 表示日を、収穫完了予定日より後の日にします。
2. 日程の「区画と畝」で、畝を選んで「選んだ畝を表示日でなくす」、または「この区画の畝をすべて表示日でなくす」を押します。
3. 「有効圃場を区画にする」か「区画を描く」で、畝のない場所を新しい区画にします。表示日からの区画になり、それまでの区画は表示日で終わります。

区画を作り直すとき、それまでの区画の扱いは次のとおりです。

| それまでの区画 | 扱い |
|---|---|
| 畝を置いたことがない | 描き直しとみなして置き換える。日程は新しい区画へ移す |
| 畝を置いたことがある、または日程が表示日より前に終わっている | 表示日で終わりにして残す。前の日付を表示すると見える |

右の「区域と区画」の一覧には、表示日にない区画も薄い文字で出ます。選ぶと図に薄く表示され、「始まる日」「なくなる日」を直したり、削除したりできます。

「畝を完全に削除」は、畝を最初からなかったことにします（作付と作業も消えます）。置きまちがいの取り消しに使います。

## 7. 作業の計画

画面の上の「日程」で開きます。圃場図で区画や畝を選んで「日程で開く」を押しても開けます。

- **区画と畝の図**: 区画を、畝の端の側から見た横長の図です。横は実寸に比例し、畝幅と隙間が cm で出ます。左に区画の作業、それぞれの畝の下にその畝の作付と作業が縦に並びます。畝や区画の作業をクリックすると、下の「作業の計画」で編集できます。
- **株の並び方**: 畝の中に、株を表す〇を、条の数 × 2 株ぶん描きます。条は実寸の条間で横に並び、千鳥なら 1 つおきの条が半分ずれます。下に条間と株間が cm で出ます。品目に条数を入れていない作付では描きません。
- **図の上での調整**: 畝はドラッグで左右に動かせ（1 cm きざみ）、端をドラッグすると幅が変わります。畝幅や隙間の数字をクリックすると cm で指定でき、後ろの畝は隙間を保ったまま一緒にずれます。変更は圃場図にも反映されます。
- **図の上での畝の追加と削除**: 畝幅、左右の隙間、本数を入れて「右端に追加」を押すと、いまある畝の続きに足します。向き、長さ、前後の隙間は、最後の畝に合わせます。図の中の「＋」（左端、畝の間、右端）を押すと、その場所に 1 列足します。前の畝から隙間をあけて置き、後ろの畝は隙間が足りないぶんだけ右へずれます。足したあと、畝の番号は左から順に振り直します。
- **くわしい設定**: 「区画と畝」の図の上の「くわしい設定」を開くと、畝の向き、長さ、前後の位置を決められます。「最初の畝の向き」は、畝がまだない区画に足すときの向き（区画の長い辺か短い辺）です。「手前の隙間」と「畝の長さ」を m で入れて、「選んだ畝に入れる」か「この区画のすべての畝に入れる」を押すと、畝が前後に動き、長さが変わります。手前は、圃場の外形で決めた視点（6 章）に近い側の端です。奥の隙間は、欄の右に出ます。
- **畝の番号**: 畝を足したときと、畝を完全に削除したときに、左から順に振り直します。「表示日で畝をなくす」でなくした畝は、一定の期間あった畝なので番号を変えず、その番号は区画を削除するまで欠番にします。プランを開いたときにも、この決まりに合わせて番号を揃えます。畝を選ぶと、「選んだ畝を表示日でなくす」「選んだ畝を完全に削除」が使えます。
- **区画の作業**: 区画を選び、「区画の作業（畝立ての前まで）」を選びます。
- **畝の作業**: 畝を選ぶと、その畝の作付が上から順に並びます。作付ごとに、見出しの行（作付の番号、品目、削除）、並べ直しの欄、作業の表があります。見出しの左のボタンで、並べ直しの欄と作業の表をたためます。いちばん下に、次の作付を足す欄があります。作付がなければ、その欄だけが出ます。「追加する作付の品目」で品目を選んで「作付を追加」を押します。畝立てから残渣処理までの作業が入った作付ができます。品目を登録してあれば、マルチを張るかどうかでひな形が決まり、品目の日数で収穫の日付が入ります。日付は、「作付を追加」の左の欄で決めます。「定植・播種をこの日に始める（前は逆算）」か「最初の作業をこの日に始める」を選び、日を入れます。日の初期値は、いちばん早く始められる日（前の作付、なければ区画の作業が終わり、すき込みのあとの 21 日などのあける日数も過ぎた日）から並べたときの日です。日を空にして、前の作付にも区画にも日付がなければ、作業の日付は空で入ります。作付の品目は、あとから「この作付の品目」で変えられます。次の作付は、前の作付に「収穫」の終了日（収穫完了予定日）が入っていると足せます。
- **ひな形から作る**（区画の作業）: 「緑肥のみ」「緑肥と太陽熱消毒の両方」「緑肥、太陽熱消毒なし」があります。「最初の作業の日」を入れておくと、目安の日数で日付が入ります。畝の作業は、「作付を追加」で入ります。品目を登録していない作付は、マルチありの並びで入ります。
- **コピー**: 作業をほかの区画や畝へ写すときは、工程表で帯を選んでコピーし、入れ先の行を選んで貼り付けます。
- **工程表**: 1 行が 1 つの区画（畝）で、左に名前の列（横に送っても残ります）、右に帯が並びます。区画の行の下に、その区画の畝の行が並びます。帯にマウスを乗せると、作業の開始日と終了日が出ます。
  - **表示期間**: 「全体」「3 か月」「1 か月」から選びます。選んだ期間がちょうど画面の幅に収まります（3 か月と 1 か月は今日を中心に）。期間の外は、横に送ると見られます。選んだ期間は、圃場ごとに覚えます。
  - **計画と実績**: 「計画と実績」の表示では、計画は太い帯、実績は計画の帯の下側に重ねた細い帯です。実績のある計画は薄く出します。
  - **名前**: 区画の名前、畝の番号、品目の名前を押すと、詳細を開きます（畝の番号は、今日その畝にある作付）。
  - **行の選択**: 行や帯を押すと、その区画（畝）を選びます（行の背景が薄い色になります）。選んだ行は、貼り付けの入れ先と、「＋ 入力する」の対象になります。下の「作業の計画」で開く区画（畝）は、工程表では切り替わりません。「区画と畝」の図で選びます。
- **工程表の上での操作**:
  - 帯をクリックで選択します。Ctrl を押しながらクリックすると、同じ行（同じ区画や畝）の帯を複数選べます。
  - 選んだ帯を左右にドラッグすると、日がずれます（1 日きざみ）。
  - 別の行へドラッグすると、その区画や畝へ移ります。Ctrl を押しながら離すとコピーです。
  - 「コピー」「切り取り」のあと、入れ先の行を押して選び、「貼り付け」で入れます（Ctrl+C、Ctrl+X、Ctrl+V でも同じ）。
  - 「削除」か Delete キーで、選んだ作業を消します。
  - 畝へ入れるときの入れ先は、その日が期間に入る作付です。作付のない畝には、作付を 1 つ作って入れます。
  - 動かしたあと、その区画や作付の作業は日付の順に並べ直されます。
- **今週やること**: 今日から 7 日間にかかる作業を出します。なければ次の作業を出します。

「作業の種類と目安の日数」の表で、作業ごとの日数と、次の作業までにあける日数を直せます。初期値は仮の値です。

### 並べ直し（逆算）

「作業の計画」の表の上で、基準にする日を決めて「並べ直す」を押すと、作業の日付をまとめて入れ直します。いまの日数は保ち、間隔は目安の日数を使います。

| 相手 | 基準 | 動き |
|---|---|---|
| 区画 | 畝立てをこの日に始められるように逆算 | 最後の作業のあとにあける日数（すき込みのあとの 21 日など）も見込んで、前へ並べる。初期値は、その区画の畝でいちばん早い最初の作業の日 |
| 畝の作付 | 定植・播種をこの日に始める | 定植・播種より前は逆算、後ろは順に並べる |
| どちらも | 最初の作業をこの日に始める | 順に並べる |

### 確認が必要な点

日程に無理があると、日程画面のいちばん上に「確認が必要な点」が出ます。行をクリックすると、その区画や作付が開きます。
同じ指摘は、工程表の帯の白い対角線（打ち消し線）、表の行の赤い印、「区画と畝」の図の ⚠ でも分かります。
工程表で帯を動かしているあいだは、動かした先の日付で見直して、対角線が付いたり外れたりします。

- 前の作業と重なっている、または順番が逆
- 次の作業までの間隔が目安より短い
- 太陽熱消毒のように期間に意味がある作業（目安が 7 日以上）が、目安より短い
- 畝の最初の作業が、区画の作業が終わる前、または必要な間隔をあけずに始まっている
- 作付が、前の作付の収穫完了予定日より前に始まっている。前の作付の収穫完了予定日が決まっていない
- 区画が始まる日より前、なくなる日以降、畝をなくす日以降に作業がある
- 日付の入っていない作業がある

指摘は知らせるだけで、保存や操作は止めません。

かかる日数が 1 日の作業は「0〜1 日」と読み替え、前後の作業と同じ日に重ねてよいものとします（畝立てとマルチ張りを同じ日に行うなど）。前の作業のあとにあける日数がある作業（すき込みのあとの 21 日など）は、1 日でも重ねません。工程表では、1 日の作業と何日かの作業が同じ日に重なったとき、その日は 1 日の作業を描き、何日かの作業はほかの日に普通の高さで描きます（切れ目の角は四角くなります）。同じ日に 1 日の作業が 2 つ以上あるときだけ、その日の中で上下の段に分けます。何日かの作業どうしが重なったとき（指摘が出る置き方）は、どの帯も隠れないよう、上下の段に分けます。

## 8. 品目と、苗数・施肥量

画面の上の「品目」で、品目ごとの設定値と、肥料の銘柄を登録します。どちらもすべてのプランで共通です。

| 設定値 | 使いみち |
|---|---|
| 畝幅、隙間 | 日程の「区画と畝」で品目を選んで畝を足すときの寸法。実際の畝幅と違うと「確認が必要な点」に出る |
| 条数、株間 | 苗数 |
| 窒素（kg/10a）、肥料 | 窒素量と、肥料の量 |
| マルチ | 作付に品目を選んだときの、ひな形の初期値（マルチあり、マルチなし） |
| 定植・播種から収穫開始まで（日）、収穫の日数 | ひな形や並べ直しで入る収穫の日付と、間隔の指摘。その品目の作付にだけ効く |
| 条間、千鳥、品種、メモ | 記録用。計算には使わない |

空の欄は計算に使いません。名前だけの品目も登録できます。

使い方は 2 通りです。

- **畝を足すときに決める**: 日程の「区画と畝」で、畝幅の左の欄から品目を選ぶと、畝幅と隙間が入ります。そのまま「右端に追加」か「＋」で足すと、その品目の作付と、ひな形の作業が付いた畝になります。
- **あとから決める**: 「作業の計画」で畝を開き、「追加する作付の品目」で選んで「作付を追加」を押します。すでにある作付は、「この作付の品目」で選び直します。登録していない品目は、「登録していない品目」のまま名前を入れます。

品目を割り当てた作付には、畝の下と「作業の計画」に苗数と肥料の量が出ます。日程画面の下の「苗と肥料の集計」には、プラン全体の品目ごとの作付の数、面積、苗数と、肥料ごとの合計が出ます。

品目の名前を変えると、作付の名前も変わります。品目を削除すると、作付には名前だけが残ります。

## 9. 変更の履歴

画面の上の「履歴」で開きます。計画を変えるたびに、何を変えたかが自動で 1 行ずつ残ります。

- **日ごとに並ぶ**: 新しい日が上で、日の中も新しい変更が上です。
- **番号**: 全体の通し番号です（#41 など）。プランをまたいでも重なりません。行をまとめたり消したりしても、番号は詰めません。
- **プラン**: 記録はプランから独立していて、どのプランでの変更かが行に出ます。品目、肥料、縮尺など、プランによらない変更は「共通」と出ます。
- **圃場**: アプリの開発日誌なので、すべての圃場の記録が並びます。圃場が 2 つ以上あるときは、「圃場の名前 / プラン」と出ます。
- **文**: その時点の名前で書きます。あとで区画や品目の名前を変えても、過去の記録の文は変わりません。値を変えた操作には、変える前と後の値が付きます。
- **まとめ**: 同じ圃場で、同じ相手への同じ操作が 30 分のうちに続いたときは、1 行にまとめ、最初の「前」の値と最後の「後」の値を残します（畝を何度も動かしたときなど）。圃場とプランの作成・コピー・名前の変更・削除は、相手の圃場やプランごとに行を分けるので、別々のプランの操作が 1 行にまとまることはありません。
- **メモ**: 日ごとに 1 つ、なぜそうしたかを書けます。すべての圃場で共通です。メモに `#41` のように番号を書くと、その行へ飛ぶボタンが出ます。
- **行をクリック**: その区画、畝、作付を開きます。圃場とプランの作成などの行は、その圃場とプランを開きます（ほかの圃場のものでも開きます）。もうないものと、いま開いていない圃場やプランの区画・畝・作付は開けません。

記録が残るのは、この仕組みを入れたあとの変更だけです。記録の行は、画面からは消せません。

### アプリの更新

アプリそのものに加えた変更は、`app/updates.json` に書きます。「履歴」の画面では、「アプリ」の札と、A の付いた番号（A12 など）で、同じ日の欄に並びます。メモからは `A12` のように触れられます。

| 項目 | 内容 |
|---|---|
| `no` | 通し番号。足すたびに 1 ずつ増やす |
| `date` | 公開した日 |
| `title` | 何ができるようになったか |
| `body` | 使う人に向けた説明 |
| `reason` | なぜ変えたか。きっかけになった困りごと |

push のたびに、できるようになったことごとに 1 件ずつ足します。
このファイルは公開されるので、圃場の場所、面積、実際の品目や時期は書きません。

### 元に戻す、やり直す

どの画面でも、Ctrl+Z で直前の操作を元に戻し、Ctrl+Y（または Ctrl+Shift+Z）でやり直せます。画面の右上のボタンでも同じです。

- **対象**: いまのプランの区域、区画、畝、作付、作業と、圃場の外形、品目、肥料、作業の種類の目安。
- **1 回ぶん**: ドラッグは離すまでが 1 回、ボタンは 1 回押すごとに 1 回です。文字を打っているあいだは、入力欄の「元に戻す」が働きます。
- **回数**: 50 回ぶんまで。画面を開き直すと、履歴はなくなります。
- **戻せない操作**: プランの切り替え・作成・コピー・削除・名前の変更、縮尺と向きの合わせ直し、下絵の読み込み、メモ。プランの切り替えなどと、縮尺・向きの合わせ直しをすると、それまでの履歴は空になります。
- **履歴**: 元に戻したこと、やり直したことも、変更の履歴に 1 行残ります。戻す前の行は消えません。

### PDF 出力

圃場図の右上と、日程の「工程表」の右上に「PDF出力」があります。押すとブラウザーの印刷の画面が開くので、出力先（送信先）で「PDF に保存」を選びます。紙は A4 です。保存するファイル名は、初めから「圃場図」「工程表」になります。

- **圃場図**: 下絵の写真は入りません。範囲は、圃場の外形がちょうど入る四角形に 3% の余白を足したもので、向きは画面と同じ（上が北）です。横長なら紙を横に、縦長なら縦に使います。選択の印は出ず、表示日の区画と畝が出ます。圃場の外形と有効圃場の各辺の長さが、辺の外側に入ります（画面の圃場図には出ません）。左下に縮尺の線が入ります。
- **工程表**: 表示期間によらず、作業のある範囲の全体を、横向きの紙の幅に収めて出します。行が多いときは、次の紙に続きます。

## 10. MCP サーバー（Claude.ai から計画と実績を読む）

計画と作業の実績を、Claude.ai のコネクタから読むためのサーバーです。読むだけで、書き換えはできません。

| 機能 | 内容 |
|---|---|
| `list_fields` | 圃場の一覧と、それぞれの面積、プラン、実際に使うプラン、最後に変更のあった日、記録の数 |
| `list_plans` | 1 つの圃場のプランの一覧と、それぞれの規模、最後に変更のあった日 |
| `get_plan` | 1 つのプランの全体。区域、耕起対象区画、畝、作付（品目、苗数、肥料の量、作業の日付）、集計、日程の無理の指摘 |
| `get_schedule` | 期間を決めた作業の一覧。同じ日の同じ作業は、場所をまとめる |
| `get_changes` | 日ごとの、計画の変更（# の番号）、メモ、アプリの更新（A の番号） |
| `get_crops` | 品目の設定値と、肥料の銘柄 |
| `get_records` | 作業の実績（作業をした日と、何日かかかった作業の終えた日、対象の畝、仕様、資材、メモ、つながる計画の作業）と、取りやめた計画の作業。期間、品目、作業、場所で絞れる |
| `get_pesticide_usage` | 実際に使うプランの作付ごとの、農薬の使用回数（本剤ごと、有効成分ごと）と上限、使用時期の基準を満たす最初の収穫日。農薬の使用基準（FAMIC）を使う部分で、Supabase の秘密の値 `FIELD_FAMIC` を `false` にすると外れる |

`list_fields` と `get_crops` のほかは、毎回 `field` で圃場を選びます（名前の一部でもよい）。
品目と肥料、日ごとのメモ、アプリの更新は、すべての圃場で共通です。

サーバーは、DB にある内容をすべて返します。区域の名前、面積、時期も含みます。
記事にするときに出さない情報は、Claude.ai の側で指定します。

### コネクタ URL の作り方

コネクタの URL は、関数の URL の末尾に「合言葉」を付けたものです。合言葉が違う呼び出しには、サーバーは何も返しません。

```
https://byhthaiwbutqstrqbwwc.supabase.co/functions/v1/field-mcp/<合言葉>
```

合言葉を作って Supabase に登録し、URL を表示します。PowerShell で、このリポジトリのフォルダーから実行します。

```powershell
$t = python -c "import secrets; print(secrets.token_urlsafe(32))"
bun x supabase secrets set "FIELD_MCP_TOKEN=$t" --project-ref byhthaiwbutqstrqbwwc
"https://byhthaiwbutqstrqbwwc.supabase.co/functions/v1/field-mcp/$t"
```

3 行目が表示した URL を控えます。合言葉はあとから取り出せないので、控え忘れたら作り直してください。

### Claude.ai に登録する

1. Claude.ai の「設定 > コネクタ」で、カスタムコネクタを追加します。
2. 上で表示された URL を入力します。
3. 認証は「No sign-in」を選びます。

### URL の扱い

**URL そのものが鍵です。** 人に見せたり、公開の場所や会話に貼ったりしないでください。
漏れた疑いがあるときは、「コネクタ URL の作り方」をもう一度実行します。合言葉が入れ替わり、古い URL は使えなくなります。

呼び出しは `field.mcp_access_log` に残ります。合言葉が違う呼び出し（`authorized` が false）が続いていないかを、ここで確かめられます。

### サーバーを配備する

画面と同じ計算をするために、`app/` の部品（`geometry.js`、`schedule.js`、`crops.js`、`updates.json`）の写しを、サーバーのフォルダーの `lib/` に置いています。
`app/` の側か `supabase/functions/field-mcp/` を変えたら、写してから、テストして配備します。合言葉は変わらないので、コネクタの登録はそのまま使えます。

```powershell
node scripts/sync-mcp-lib.mjs
node --test "tests/*.test.mjs"
```
