# field_plan

いのーファームの圃場の計画と管理を、ブラウザーで行うアプリです。
計画は PC で作り、作業内容はスマホで確認します。見られるのはログインした本人だけです。

## 1. 考え方

計画は、実際の作業の順に、次の 4 つの入れ物で持ちます。

| 入れ物 | 内容 |
|---|---|
| 有効圃場 | 耕してよい場所。物置、井戸、通路を除いた範囲 |
| 耕起対象区画 | 有効圃場を線で分けたもの。**畝立ての前まで**の作業（心土破砕、ロータリー、太陽熱消毒、緑肥など）を区画ごとに計画する |
| 畝 | 区画の中に置く四角形。前後と左右の隙間が通路になる |
| 作付 | 1 本の畝で、**畝立てから収穫まで**の 1 回ぶん。品目と作業（畝立て、マルチ張り、定植・播種、収穫、残渣処理）を持つ |

時間の決まりは次のとおりです。

- 畝には、前の作付の収穫完了予定日のあとに、次の作付を置けます。回転の速い品目は、同じ畝に作付が 2 つ、3 つと並びます。
- 収穫完了予定日より後の日付で、畝をなくせます。
- 畝のない場所は、その日付から新しい耕起対象区画に設定し直せます。前の日付を表示すれば、前の区画と畝が見えます。

### 作る順番

1. 圃場と区域の作図（済み）
2. 耕起対象区画、畝、作付と、その作業の計画（済み）
3. 日程の逆算と警告（済み）
4. 品目の設定値からの苗数、施肥量の計算（済み）
5. 作業の実績（実績と管理作業の計画の入力、計画とのつながりまで作った。[計画](docs/actuals-plan.md)）

### 計算式

| 項目 | 式 |
|---|---|
| 苗数 | 切り捨て（畝長 ÷ 株間）× 条数 |
| 畝の面積 | 畝長 × 畝幅 |
| 窒素量 | 畝の面積 × 10 a あたりの窒素量 ÷ 1,000 ㎡ |
| 肥料の量 | 窒素量 ÷ 肥料の窒素成分（%） |

### テーブル

```
fields（圃場。active_plan_id で実際に使うプランを指す）
├─ backdrops（下絵の位置合わせ）
├─ work_logs（作業の記録。プランではなく圃場に付ける）
│  ├─ work_log_targets（対象の畝・区画と、つながる計画の作業）
│  └─ work_log_inputs（使った資材）
└─ plans（プラン）
   └─ zones（区域。有効圃場、物置、井戸、通路など）
      └─ blocks（耕起対象区画。始まる日となくなる日を持つ）
         ├─ works（畝立ての前までの作業）
         └─ beds（畝。なくなる日を持つ）
            └─ plantings（作付）
               └─ works（畝立てから後の作業）

work_types（作業の種類と目安の日数。plannable が false の種類は記録だけに使う）、crops（品目の設定値）、fertilizers（肥料）、
dev_notes（開発日誌のメモ）は、すべての圃場で共通

weather_daily（アメダスの観測所ごとの日ごとの気温と降水量）、
famic_imports・famic_products・famic_uses（FAMIC の農薬登録情報。画面からは読むだけ）、
rac_imports・rac_codes（有効成分ごとの RAC コード。画面からは読むだけ）、
app_compat（この DB を使ってよい画面の版。画面からは読むだけ）も共通
```

圃場はいくつも持てます。外形、下絵、プランは圃場ごとです。
図形は、圃場の基準点を原点としたメートル座標の多角形で持ちます。
区画、畝、作付、作業はどれもプランの ID を持ち、プランごとにまとめて読み込みます。

## 3. データを守る仕組み

- テーブルは `field` スキーマに置き、RLS で `field.owners` に登録した利用者にだけ読み書きを許します。
- 下絵の画像（集成図など）には地番や氏名が写っていることがあるので、リポジトリに入れず、非公開のストレージ（`field-plan`）に置きます。
- 農作業日記には、ほかの方の氏名や連絡先が入ります。日記は `inoo_farm` の `diary` スキーマにあり、API には出していません。画面は `sql/diary.sql` の関数だけを通して読み書きし、関数は `field.owners` に登録した本人でなければ止まります。写真は非公開のストレージ（`diary-photos`）に置きます。本物の日記は、テストにも画面の見本にも使いません。
- 圃場の場所、面積、作付の予定などは、このリポジトリに書きません。DB にだけ置きます。
- 計画の表の行を足す・変える・消すたびに、DB が変える前と後の行を `field.audit_log` に残します。DB が一緒に消した行（区画を消したときの畝など）も残ります。画面からは読めず、事故を調べたり、消えた行を戻したりするときに、DB に直接つないで読みます。1 年より古い行は、毎日 3:30 に pg_cron が消します。開発日誌のための変更の記録（`field.changes`）とは別のものです。
- 共用の DB 全体を、毎日 2 回（16:23 と 4:23 が目安）バックアップします。暗号化してから Supabase の外の非公開の置き場に送り、直近 8 日、週ごと 35 日、月ごと 370 日のぶんを残します。仕組みと戻し方は、非公開のリポジトリ `shared_db_backup` にあります。下絵の画像と日記の写真は、DB とは別に、新しいものだけを暗号化して同じ置き場に写します。消えた行を戻すときは、まず `field.audit_log` を見て、それで戻せないときにバックアップを使います。

## 4. 最初の準備

一度だけ行います。

1. Supabase の SQL Editor で `sql/field.sql` を実行します（実行済み）。
2. Integrations > Data API > Settings（または Project Settings > Data API）の Exposed schemas に `field` を加えます。
3. Authentication > Users でログイン用の利用者を作ります。
4. その利用者の ID を登録します。

   ```sql
   insert into field.owners (user_id) values ('利用者の ID');
   ```

5. 2 週間気温予報の関数を配備します（配備済み）。

   ```
   bun x supabase functions deploy field-weather --remote=byhthaiwbutqstrqbwwc
   ```

6. GitHub Actions が気象の値（毎日、`weather.yml`）、県のページのニュース（1 日 2 回、`news.yml`）と FAMIC の農薬登録情報（週に 1 回、`famic.yml`）を入れるために、取り込み係の利用者を作ります（作成済み）。Supabase Auth に利用者を作って `field.importers` に登録し、そのメールアドレスとパスワードを、GitHub のリポジトリの Settings > Secrets and variables > Actions に `FIELD_IMPORTER_EMAIL`、`FIELD_IMPORTER_PASSWORD` として置きます。取り込み係にできるのは、気象の値と FAMIC の入れ替え、ニュースを読むことと足すことだけです（確認した印は変えられません）。DB の接続文字列は GitHub に置きません。

### 画面の移り方

上のタブ（圃場図、日程、品目、日記、履歴）と作付の詳細は、それぞれ URL を持ちます（`#map`、`#crops`、`#diary`、`#journal`、日程は開いている区画を付けて `#schedule/block/区画の ID`、作付の詳細は `#detail/planting/作付の ID`）。前にあった区画の詳細の URL（`#detail/block/区画の ID`）は、日程の画面でその区画を開きます。画面を移るたびにブラウザーの履歴に積むので、戻る・進むのボタンで前の画面に戻れます。再読み込みやブックマークでも、同じ画面を開きます。作付の詳細で隣の作付へ移るときは履歴を積まないので、何本か見てからでも、戻る 1 回で日程に戻ります。

URL を開いたときに URL に画面が書かれていなければ、PC もスマホも圃場図から開きます。圃場図の上には、警告と、［遅れている作業｜今週やること｜最近の実績｜ニュース］のタブの欄を出します。タブの欄は、初めは「今週やること」を開きます。遅れている作業があるときは、そのタブの名前に ⚠ と件数を付けます。ニュースのタブには、県のページに載った新しい記事（リンクの文をそのまま）を未読として出し、未読があればタブの名前に ⚠ と件数を付けます。行の右端の「確認」を押すと既読へ移り、「既読を見る」で既読の一覧（確認した新しい順に 30 件）に切り替わります。既読から「未読に戻す」もできます。PC では欄の高さを 150px に決めていて（図の位置が日によって動かないように）、はみ出す分は欄の中で送ります。スマホでは中身に合わせた高さです。

ヘッダーの左上には、ロゴの横に、開いている圃場の名前と、その下にプランの名前を出します（圃場を開く前は「圃場計画」）。名前の欄は、ヘッダーが 1 段に収まる空きまで広げ、収まらない名前は末尾を「…」で省きます。省いても入らない幅では、ヘッダーを 2 段に折り返します。実際に使うプランでないプランを開いているときは、プランの名前を赤い太字にして「⚠」を付けます。

ロゴと名前を押すと、メニューが開きます。上から、開いている圃場とプラン（省かずに出す）、「圃場とプランを選ぶ…」、「圃場の設定…」（PC だけ）、ログインしているアカウント（メールアドレス）とログアウトです。閉じるときは、メニューの外を押すか、Esc を押すか、ロゴと名前をもう一度押します。ログアウトするとき、日記の書きかけがこの端末に残っていれば、消してよいかを確かめてから消します（日記にはほかの方の名前も入るため）。

### 圃場とプランの窓

メニューの「圃場とプランを選ぶ…」で開きます。左（スマホでは上）に圃場、右（下）に選んだ圃場のプランが並びます。圃場を押すと、その圃場のプランが出ます。プランの行には、名前、「実際に使う」「開いている」の札、規模（区画と畝の数）と最後の変更の日が出ます。

- **開く**: プランの「開く」で、そのプランを開いて窓を閉じます。ほかの圃場のプランなら、その圃場ごと開きます。
- **「…」のメニュー**: 圃場は「名前を変更」「削除」、プランは「名前を変更」「コピー」「実際に使うプランにする」「削除」です。開いていない圃場やプランも、開かずに操作できます。押したときに保存します。
- **作る**: 「＋ 新しい圃場」で圃場を足すと、空のプラン「プラン1」が 1 つ付き、その圃場を開きます。「＋ 新しいプラン」は、選んでいる圃場にプランを足します（開いている圃場なら、そのプランを開きます）。コピーしたプランは、開かずに一覧に足します。
- **消せないもの**: 圃場が 1 つだけのときの圃場、圃場の最後のプラン、実際に使うプランは消せません。圃場を消すと、外形、下絵（画像も）、プランと、その中の区域・区画・畝・日程ごと消えます。開発日誌の記録とメモは残ります。
- **閉じる**: 右上の「閉じる」か Esc で閉じます。

## 5. 圃場の作図

圃場とプランは、ヘッダーのメニューの「圃場とプランを選ぶ…」で切り替えます（4 章）。下絵、外形、縮尺、向きと位置、気象は、メニューの「圃場の設定…」の窓で設定します（下の「圃場の設定の窓」）。

ふだんの圃場図は、図形を選ぶ・見るためのもので、図形は動きません（なぞると図が動きます）。図の枠の左上に「表示日」と「下絵」の切り替え、右上に「✎ 図を編集」と「PDF出力」を重ねて出します。区域と耕起対象区画を描いたり動かしたりするときは「✎ 図を編集」を押します。図の枠が色付きになり、枠の上端に道具の帯（［選択・移動］［区域▾］［耕起対象区画▾］、操作の説明、「保存する」「閉じる」）が出ます。初めの道具は「選択・移動」です。「区域▾」「耕起対象区画▾」は押すとメニューが開き、描き方を選ぶとメニューが閉じてその道具になります。寸法や分ける線の向きの欄は、その道具を選んだときだけ帯の下に出ます。図形を消すボタン（右の欄の「区域を削除」など）も編集中だけ出します。

図の編集は書きかけです。編集中の変更（図形だけでなく、そのあいだに入れた実績なども）と変更の記録は、帯の「保存する」を押すまで保存しません。ヘッダーの「元に戻す」「やり直す」は、編集中も使えます。「保存する」でまとめて保存し、編集は続けられます。「閉じる」で帯を閉じます。保存していない変更があれば、捨ててよいかを確かめ（「捨てて閉じる」「編集を続ける」）、捨てると編集を始める前の状態に戻します。編集中にメニューの「圃場とプランを選ぶ…」「圃場の設定…」を選ぶと、先に編集を閉じます。スマホの幅では「図を編集」を出しません。
外形、下絵とその縮尺・向き、プランは圃場ごとなので、ほかの圃場の図形は変わりません。前に開いていた圃場とプランは、次に開いたときにも開きます。

1. 圃場の設定の窓の「下絵」のタブの「画像を読み込む」で、下絵にする図（集成図や航空写真）の画像を読み込みます。ヘッダーの下のお知らせに、送った割合が出ます。60 秒のあいだ少しも進まなければ止めて知らせるので、回線を確かめるか、画像を小さくしてから読み込み直してください。
2. 圃場の設定の窓の「外形」のタブの「外形を描く」で、圃場の角を順にクリックし、最初の点をクリックするか「確定」で閉じます。同じ下絵の上の離れた場所も同じ圃場として扱うときは、もう一度「外形を描く」で、その部分を描き足します（いまの外形は置き換わりません）。部分は一覧に「圃場の外形 1」「圃場の外形 2」…と並び、圃場の面積は部分の合計です。このタブでは、図の上の外形を押すと選べ、角の丸のドラッグで角を動かし、辺の中ほどの丸のドラッグで角を足します。「選んだ角を削除」「選んだ外形を削除」もここにあります。描き直すときは、その部分を消してから描きます。ほかの設定と同じく、「保存する」で保存します。
3. 圃場の設定の窓の「計測」のタブで、縮尺を合わせます。「距離を測る」は 2 点を、「面積を測る」は範囲の角を順にクリックして最初の点で閉じます。押しているあいだ、今の縮尺での長さ（面積）が図に出ます。2 点目（閉じたところ）で「今の縮尺では 20.10 m です。実際の距離（m）は？」（面積は ㎡）と尋ねるので、実際の値を入れると、その比で縮尺が直ります。キャンセルすれば何も変わらないので、ただ測るのにも使えます。現地で測るまでは、登記などで分かっている面積の範囲を「面積を測る」で囲み、測ったあとは「距離を測る」で直します。図形と下絵が一緒に伸び縮みします。あとから下絵を差し替えるときは、下の「下絵を差し替える」を見てください。
4. 「✎ 図を編集」の「区域▾」のメニューで、区域の種類（有効圃場、物置、井戸、通路、残渣処理場、その他）を選び、次のどれかで描きます。
   - **多角形**: 角を順にクリックします。
   - **四角形**: 対角の 2 点をドラッグします。
   - **寸法を指定**: 辺に沿う長さと奥行きを入れ、置く場所をクリックします。

四角形は、いちばん近い外形の辺に平行になります。変更は、帯の「保存する」で保存します。スマホの幅では閲覧だけになります。

編集中に図形を選ぶと、それを囲んでいる図形の各辺と、近くの図形までの距離が出ます（区域は外形とほかの区域、区画は有効圃場とほかの区画、畝は区画と両隣の畝）。位置を決める方法は 3 つあります。

- 距離の数字をクリックして、その距離を数値で指定する（例: 圃場の端から 2 m）
- 矢印キーで 10 cm ずつ動かす（Shift を押しながらだと 1 m）
- ドラッグで動かす

区域と区画の大きさは、次の方法で変えます。

- 辺の中ほどの丸をドラッグすると、その辺が平行に動きます。
- 辺の長さの数字をクリックすると、長さを m で指定できます。辺の始まりの頂点は動かず、終わりの側がずれます。

圃場の外形だけは、辺の中ほどの丸をドラッグすると、そこに頂点が足されます（圃場の設定の窓の「外形」のタブで）。

有効圃場を動かすと中の区画と畝も、区画を動かすと中の畝も一緒に動きます。

図形は「圃場の外形 ⊇ 区域 ⊇ 耕起対象区画 ⊇ 畝」の順に入っているはずです（外形が離れた部分に分かれているときは、区域はどれか 1 つの部分に入っていればよい）。入れ物からはみ出した図形は、図では赤い点線になり、圃場図のすぐ上に赤い文字で出ます。文をクリックすると、その図形が選ばれます。上部の「圃場図」のタブには警告の件数が付き、区域と耕起対象区画の一覧でも、はみ出している行に ⚠ が付きます。区画と畝は、表示日にあるものだけを見ます。大きさを変えたときは、中の図形は自動では動かないので、この表示で確かめてください。

外形（離れた部分を含む）と下絵は圃場に 1 つで、区域、区画、畝、日程はプランごとに持ちます。プランは新規、コピー、名前の変更、削除ができます。

### 圃場の設定の窓

メニューの「圃場の設定…」で開きます（PC だけ）。左に図、右に「元に戻す」「やり直す」と、［下絵｜外形｜計測｜位置と向き｜気象］のタブが並びます。

- **図**: 圃場図の図そのものを、窓を開いているあいだだけ窓の中へ移します。拡大・縮小・移動はいつもどおりで、図形を選んだり動かしたりできるのは、「外形」のタブでの外形だけです。窓を開くと、圃場図の「図を編集」は終わります。「距離を測る」「面積を測る」「図形に位置を合わせる」の点は、この図の上でクリックします。押した点は白い縁の付いた赤い点で出し、最後に押した点からマウスの位置まで線（面積は多角形）を伸ばします。
- **書きかけ**: 窓の中の調整（下絵の読み込み、外形、縮尺、位置、向き）と気象の設定は、「保存する」を押すまで保存しません。調整と気象の欄の変更は、窓の中の「元に戻す」「やり直す」で 1 回ずつ行き来できます（「図形を下絵の縮尺に合わせる」なども、保存するまでは戻せます）。
- **保存する**: 書きかけをまとめて保存します。窓は閉じないので、続けてほかのタブを設定できます。保存すると、窓の中の「元に戻す」の履歴は空になります。図形の大きさや向きを変える調整が入っているときは、この圃場のすべてのプランの図形に当てることを確かめてから保存します（保存したあとは「元に戻す」で戻せません）。
- **閉じる**: 右上の「閉じる」か Esc で閉じます。保存していない設定があれば、捨ててよいかを確かめ、捨てると開く前の状態に戻します（読み込んだ画像は、画像の置き場に残ります）。
- **下絵を表示**: 「下絵」のタブと、圃場図の枠の左上（表示日の隣。スマホでも出す）にあります。どちらも同じ切り替えで、保存や「元に戻す」の対象ではありません。

### 下絵を差し替える

下絵には 2 つの役割があります。圃場の設定の窓の「下絵」のタブに、いまの下絵がどちらかが出ます。

| 役割 | どんな下絵か | 縮尺・向きを変えると |
|---|---|---|
| 図形を描く下絵 | 図形のない圃場に読み込んだ下絵（ふつうは圃場の最初の 1 枚） | 図形も一緒に伸び縮み・回転する |
| 図形に合わせて置いた下絵 | 図形がすでにある圃場に読み込んだ下絵 | 下絵だけが変わり、図形は変わらない |

図形に合わせて置いた下絵は、次の順に合わせます。

1. **縮尺**: 「計測」のタブの「距離を測る」で、下絵に描かれた尺度の線の両端など、実際の距離が分かっている 2 点をクリックし、距離を入れます。下絵が、描かれた尺度のとおりの大きさになります。2 点の中ほどは動きません。
2. **位置と向き**: 「図形に位置を合わせる」で、下絵の上の目印（角や杭など）と、それが来るべき図形の上の点を、順にクリックします。下絵が平行移動します。続けて 2 つ目の目印と図形の上の点をクリックすると、向きも合わせます。大きさは変えません。位置だけでよければ、1 組目のあとで Esc を押します。
3. **大きさの食い違い**: 2 組で合わせると、図形と下絵の大きさがどれだけ違うかが出ます（例: 図形は、この下絵の尺度より 2.3% 大きくなっています）。図形のほうが誤っているときは「図形を下絵の縮尺に合わせる」で、この圃場のすべてのプランの図形の大きさを直します。下絵のほうが不正確なら、そのままにします。

「下絵の上と北のずれ」の欄で向きを変えたときも、図形に合わせて置いた下絵では、下絵だけが画面の真ん中のまわりに回ります。
「面積を測る」も、図形に合わせて置いた下絵では、下絵の縮尺だけを直します（囲んだ範囲の真ん中は動きません。図形は変わりません）。図形の大きさのほうを直すときは、「図形を下絵の縮尺に合わせる」を使います。

**解像度だけを変えた画像**: 前の下絵と縦と横の比が同じ画像を読み込むと、「同じ範囲として引き継ぐ」か尋ねます。引き継ぐと、画素の数の比から、前の下絵の縮尺・位置・向きをそのまま移します。比が 1% より違う画像は、仮の縮尺（1 画素 = 10 cm）で置きます。

## 6. 耕起対象区画と畝

### 表示日

圃場図は、上の「表示日」にある区画と畝だけを描きます。表示日はブラウザーが圃場ごとに覚えていて、次にその圃場を開いたときも同じ日になります（開いていたプランと、工程表の表示も、圃場ごとに覚えます）。区画を作り直すとき、畝をなくすときは、表示日がその日付になります。
最初に作る区画と畝は「最初から」ある扱いで、表示日に関係なく見えます。

### 区画を作る

「✎ 図を編集」の「耕起対象区画▾」のメニューから選びます。

| 道具 | 使い方 |
|---|---|
| 有効圃場を区画にする | 有効圃場をクリックすると、全体が 1 つの区画になる |
| 線で分ける | 区画（または区画のない有効圃場）の中をクリックし、近いほうの端からの距離を数値で決めて 2 つに分ける。線の向きは、短い辺に平行か、長い辺に平行かを選ぶ |
| 区画を描く | 有効圃場の中で対角の 2 点をドラッグする |

有効圃場の一部だけを耕すときは、線で分けたあと、耕さない区画を削除します。
畝をまたぐ位置では分けられません。区画を分けると、畝は入っている側に付き、区画の作業は両方に同じものが入ります。

### 畝を見る視点

畝の手前と奥、日程の「区画と畝」の図の左右、畝の番号の順は、圃場を見る視点で決まります。
右の一覧で「圃場の外形」を開き、「視点 1」と「視点 2」に、立つ側の辺を選びます。辺は「辺 1 → 2（北東側、12.50 m）」のように出て、図には頂点の番号と、視点の矢印が出ます。外形が離れた部分に分かれているときは、どの部分の辺でも選べ（「外形 2 の辺 1 → 2」のように出ます）、平行でない 2 つの視点の向きで、すべての部分の区画の畝の並びが決まります。

- 畝の長い辺が、視点 1 の見る向きに近ければ視点 1 から、直角に近ければ視点 2 から見ます。視点 2 には、視点 1 と直角の辺を選びます。
- 手前は、その視点に近い側の端です。畝の番号は、その視点から見て左から順です。
- 決めていないときは、図の下（南）からと、図の左（西）から見ます。
- 視点を変えると、畝の番号を振り直します。ほかのプランは、開いたときに振り直します。

### 畝を並べる

畝の追加、移動、削除は、日程の画面の「区画と畝」の図で行います（7 章）。圃場図では、畝は見るだけで、ドラッグや矢印キーでは動きません。畝を選ぶと、右の一覧に幅と長さ、作付が出て、「作付の詳細を開く」で、図に出ている作付の詳細を開けます（畝の品目名を押しても開きます）。区画を選んだときは、「日程で開く」で日程の画面へ移れます。
区域や区画を削除すると、中の畝も一緒に消えます。

### 畝をなくす、区画を設定し直す

1. 表示日を、収穫完了予定日より後の日にします。
2. 日程の「区画と畝」で、畝を選んで「選んだ畝を表示日でなくす」、または「この区画の畝をすべて表示日でなくす」を押します。
3. 「有効圃場を区画にする」か「区画を描く」で、畝のない場所を新しい区画にします。表示日からの区画になり、それまでの区画は表示日で終わります。

区画を作り直すとき、それまでの区画の扱いは次のとおりです。

| それまでの区画 | 扱い |
|---|---|
| 畝を置いたことがない | 描き直しとみなして置き換える。日程は新しい区画へ移す |
| 畝を置いたことがある、または日程が表示日より前に終わっている | 表示日で終わりにして残す。前の日付を表示すると見える |

右の「区域と区画」の一覧には、表示日にない区画も薄い文字で出ます。選ぶと図に薄く表示され、「始まる日」「なくなる日」を直したり、削除したりできます。

「畝を完全に削除」は、畝を最初からなかったことにします（作付と作業も消えます）。置きまちがいの取り消しに使います。その畝を対象にした作業の記録からは、その畝を対象から外し、ほかに対象のない記録は記録ごと消します。何件の記録が変わるかは、削除の前の確認に出ます。区画や区域を削除したときも、中の畝と区画について同じようにします。

## 7. 作業の計画

画面の上の「日程」で開きます。圃場図で区画を選んで「日程で開く」を押しても開けます。日程の画面は、1 つの区画の中のことを扱います（圃場の全体の今週やること、最近の実績、警告、すべての区画の工程表は、圃場図の画面に出します）。

- **区画・畝の欄**: いちばん上の欄で、区画か畝を選びます。区画の行（太字）の下に、その区画の畝の行（区画1 畝1 品目名）が並びます。区画を選ぶと、作付の詳細と同じ形の頭（前後の区画へのボタン、区画の名前、面積・畝の本数、「＋ 作業を入力」、日記のボタン、表示の切り替え）の下に、その区画の「区画と畝」「区画の作業の計画と実績」「工程表」が並びます。畝を選ぶと、その畝の作付の詳細（今日その畝にある作付、なければ最後の作付）を開きます。作付の詳細の上にも同じ欄が出るので、そこから別の区画や畝へ移れます。作付のない畝を選ぶと、「作業を入力する」の窓の工程の計画を、その畝で開きます（作付を足せます）。確認が必要な点のある区画と畝には ⚠ が付き、選んだ区画（畝）の確認が必要な点が、区画の頭（作付の詳細の頭）の下に並びます。
- **区画の作業の計画と実績**: 区画の作業の計画と、それにつながる実績、計画にない実績（区画に入れた記録）を、日付の順に並べます。表示（計画・実績・計画と実績）は、区画の頭の切り替えと工程表で共通です。実績が計画とずれたときは「計画との差」が出て、「後ろを実績に合わせて並べ直す」で後ろの作業をずらせます。区画と区画の中の作付に日記があれば、区画の頭に日記のボタンが出ます（9 章）。前にあった「区画の詳細」の画面は、この欄に置き換えました。
- **苗と肥料の集計**: 区画の頭の面積・畝の行を押すと「苗と肥料の集計（この区画）」が開き、選んだ区画の品目ごとの作付の数、面積、苗数と、肥料ごとの合計が出ます。
- **作業の種類と目安の日数**: 「品目」の画面の、肥料の表の下にあります（PC だけ）。

- **区画と畝の図**: 区画を、畝の端の側から見た横長の図です。横は実寸に比例し、畝幅と隙間が cm で出ます。左に区画の作業、それぞれの畝の下にその畝の作付と作業が縦に並びます。区画の作業の欄を押すと、「作業を入力する」の窓の工程の計画を、その区画で開きます。畝の下の作付の欄を押すと、その作付の詳細を開きます（作付のない畝は、窓の工程の計画をその畝で開きます）。畝を押すと、その畝を選びます（スマホでは、作付の詳細を開きます）。
- **株の並び方**: 畝の中に、株を表す〇を、条の数 × 2 株ぶん描きます。条は実寸の条間で横に並び、千鳥なら 1 つおきの条が半分ずれます。下に条間と株間が cm で出ます。品目に条数を入れていない作付では描きません。
- **図の上での調整**: 畝はドラッグで左右に動かせ（1 cm きざみ）、端をドラッグすると幅が変わります。畝幅や隙間の数字をクリックすると cm で指定でき、後ろの畝は隙間を保ったまま一緒にずれます。変更は圃場図にも反映されます。
- **図の上での畝の追加と削除**: 畝幅、左右の隙間、本数を入れて「右端に追加」を押すと、いまある畝の続きに足します。向き、長さ、前後の隙間は、最後の畝に合わせます。図の中の「＋」（左端、畝の間、右端）を押すと、その場所に 1 列足します。前の畝から隙間をあけて置き、後ろの畝は隙間が足りないぶんだけ右へずれます。足したあと、畝の番号は左から順に振り直します。
- **くわしい設定**: 「区画と畝」の図の上の「くわしい設定」を開くと、畝の向き、長さ、前後の位置を決められます。「最初の畝の向き」は、畝がまだない区画に足すときの向き（区画の長い辺か短い辺）です。「手前の隙間」と「畝の長さ」を m で入れて、「選んだ畝に入れる」か「この区画のすべての畝に入れる」を押すと、畝が前後に動き、長さが変わります。手前は、圃場の外形で決めた視点（6 章）に近い側の端です。奥の隙間は、欄の右に出ます。
- **畝の番号**: 畝を足したときと、畝を完全に削除したときに、左から順に振り直します。「表示日で畝をなくす」でなくした畝は、一定の期間あった畝なので番号を変えず、その番号は区画を削除するまで欠番にします。プランを開いたときにも、この決まりに合わせて番号を揃えます。畝を選ぶと、「選んだ畝を表示日でなくす」「選んだ畝を完全に削除」が使えます。
- **作業の計画を直す**: 区画の作業と、畝の作付ごとの作業は、「作業を入力する」の窓の工程の計画で直します（次の「作業を入力する窓」）。作付を足すときは、品目と日の決め方（「定植・播種をこの日に始める（前は逆算）」か「最初の作業をこの日に始める」）と日を選んで「作付を追加」を押すと、畝立てから残渣処理までの作業が入った作付ができます。日の初期値は、いちばん早く始められる日（前の作付、なければ区画の作業が終わり、すき込みのあとの 21 日などのあける日数も過ぎた日）から並べたときの日です。次の作付は、前の作付に「収穫」の終了日（収穫完了予定日）が入っていると足せます。
- **ひな形から作る**（区画の作業）: 「緑肥のみ」「緑肥と太陽熱消毒の両方」「緑肥、太陽熱消毒なし」があります。窓の工程の計画の「ひな形から作る・並べ直す」で、最初の作業の日を入れておくと、目安の日数で日付が入ります。畝の作業は、「作付を追加」で入ります。品目を登録していない作付は、マルチありの並びで入ります。
- **コピー**: 作業をほかの区画や畝へ写すときは、工程表で帯を選んでコピーし、入れ先の行を選んで貼り付けます。
- **工程表**: 圃場図では図の下に、すべての区画と畝を出します。日程の画面では、選んだ区画とその畝だけを出します（同じ工程表で、表示・表示期間・コピーした作業は共通です。画面を移ると、帯の選択は外れます）。区画の名前を押すと、日程の画面でその区画を開きます。圃場図の画面では、最後に工程表を押したときだけ、Delete や Ctrl+C などのキーが工程表に効きます（図を押したあとは図に効きます）。1 行が 1 つの区画（畝）で、左に名前の列（横に送っても残ります）、右に帯が並びます。区画の行の下に、その区画の畝の行が並びます。帯にマウスを乗せると、作業の開始日と終了日が出ます。
  - **表示期間**: 「全体」「3 か月」「1 か月」から選びます。選んだ期間がちょうど画面の幅に収まります（3 か月と 1 か月は今日を中心に）。期間の外は、横に送ると見られます。選んだ期間は、圃場ごとに覚えます。
  - **計画と実績**: 「計画と実績」の表示では、計画は太い帯、実績は計画の帯の下側に重ねた細い帯です。実績のある計画は薄く出します。
  - **名前**: 区画の名前を押すと、日程の画面でその区画を開きます。畝の番号、品目の名前を押すと、作付の詳細を開きます（畝の番号は、今日その畝にある作付）。
  - **行の選択**: 行や帯を押すと、その区画（畝）を選びます（行の背景が薄い色になります）。選んだ行は、貼り付けの入れ先と、圃場図の右下の「＋ 入力する」の対象になります（「＋ 入力する」は圃場図の画面だけに出します。日程の画面と作付の詳細では、頭の「＋ 作業を入力」を使います）。
- **工程表の上での操作**:
  - 帯をクリックで選択します。Ctrl を押しながらクリックすると、同じ行（同じ区画や畝）の帯を複数選べます。
  - 選んだ帯を左右にドラッグすると、日がずれます（1 日きざみ）。
  - 別の行へドラッグすると、その区画や畝へ移ります。Ctrl を押しながら離すとコピーです。
  - 「コピー」「切り取り」のあと、入れ先の行を押して選び、「貼り付け」で入れます（Ctrl+C、Ctrl+X、Ctrl+V でも同じ）。
  - 「削除」か Delete キーで、選んだ作業を消します。
  - 畝へ入れるときの入れ先は、その日が期間に入る作付です。作付のない畝には、作付を 1 つ作って入れます。
  - 動かしたあと、その区画や作付の作業は日付の順に並べ直されます。
- **今週やること**: 今日から 7 日間にかかる作業を出します。なければ次の作業を出します。圃場の全体の作業なので、圃場図の上に出します。

「品目」の画面の「作業の種類と目安の日数」の表で、作業ごとの日数と、次の作業までにあける日数を直せます。初期値は仮の値です。

### 作業を入力する窓

区画の頭と作付の詳細の頭の「＋ 作業を入力」、圃場図の右下の「＋ 入力する」で開きます。上のタブで、入れるものを選びます。

| タブ | 入れるもの | 初めに開く入口 |
|---|---|---|
| 工程の計画 | 区画の作業（畝立ての前まで）と、畝の作付ごとの作業（畝立てから残渣処理まで） | 区画の頭 |
| 管理作業の計画 | 防除、追肥、除草、灌水、株の手入れ、その他の予定 | （タブで選ぶ） |
| 実績 | 実際に行った作業 | 作付の詳細、圃場図、今週やること |

- **保存**: どのタブも、入れた内容は「保存する」を押したときに保存し、「キャンセル」で捨てます。
- **捨ててよいかの確かめ**: 保存していない入力があるまま、タブを替える、閉じる（「閉じる」「キャンセル」、Esc、ブラウザーの戻る）、工程の計画の「直す相手」を替えると、捨ててよいかを確かめます。捨てると、入力は消えます（タブを替えても、前のタブの入力は残しません）。何も変えていなければ、確かめません。
- **管理作業の計画と実績の行き来**: この 2 つのタブは、入れた内容（日付、作業の種類、対象、資材、メモ）をそのまま持って、確かめずに行き来できます。実績で管理作業でない種類（定植・播種など）を選んでいるときと、つなぐ計画に印を付けているときは、計画のタブへは持っていけないので、捨ててよいかを確かめます。
- **相手の引き継ぎ**: タブを替えると、選んでいた区画や畝（工程の計画の「直す相手」、または開いた画面の区画や作付）を、次のタブの対象に入れます。
- **工程の計画**: 「直す相手」で、区画の作業か畝を選びます。作業 1 件をカード 1 枚にして、作業の種類、開始日〜終了日、日数・前との間隔・実績、メモ（「メモ ＋」で開く）、↑ ↓ 削除を並べます。確認が必要な点のある作業は、カードの枠を赤くし、理由をカードに書きます。区画では「ひな形から作る・並べ直す」、畝では作付ごとの品目、「この作付を削除」、「並べ直す」と、いちばん下の「次の作付を追加」が使えます。スマホでも直せます。
- **実際に使うプランがないとき**: 工程の計画のタブだけが使えます（工程の計画は、どのプランでも直せます）。


### 並べ直し（逆算）

窓の工程の計画の「並べ直す」で、基準にする日を決めて「並べ直す」を押すと、作業の日付をまとめて入れ直します。いまの日数は保ち、間隔は目安の日数を使います。

| 相手 | 基準 | 動き |
|---|---|---|
| 区画 | 畝立てをこの日に始められるように逆算 | 最後の作業のあとにあける日数（すき込みのあとの 21 日など）も見込んで、前へ並べる。初期値は、その区画の畝でいちばん早い最初の作業の日 |
| 畝の作付 | 定植・播種をこの日に始める | 定植・播種より前は逆算、後ろは順に並べる |
| どちらも | 最初の作業をこの日に始める | 順に並べる |

### 確認が必要な点

日程に無理があると、圃場図のいちばん上の「警告」の欄に出ます（図形のはみ出しと同じ欄。件数は「圃場図」のタブに出ます）。行をクリックすると、「作業を入力する」の窓の工程の計画を、その区画や作付で開きます。
同じ指摘は、工程表の帯の白い対角線（打ち消し線）、表の行の赤い印、「区画と畝」の図の ⚠ でも分かります。
工程表で帯を動かしているあいだは、動かした先の日付で見直して、対角線が付いたり外れたりします。

- 前の作業と重なっている、または順番が逆
- 次の作業までの間隔が目安より短い
- 太陽熱消毒のように期間に意味がある作業（目安が 7 日以上）が、目安より短い
- 畝の最初の作業が、区画の作業が終わる前、または必要な間隔をあけずに始まっている
- 作付が、前の作付の収穫完了予定日より前に始まっている。前の作付の収穫完了予定日が決まっていない
- 区画が始まる日より前、なくなる日以降、畝をなくす日以降に作業がある
- 日付の入っていない作業がある

指摘は知らせるだけで、保存や操作は止めません。

かかる日数が 1 日の作業は「0〜1 日」と読み替え、前後の作業と同じ日に重ねてよいものとします（畝立てとマルチ張りを同じ日に行うなど）。前の作業のあとにあける日数がある作業（すき込みのあとの 21 日など）は、1 日でも重ねません。工程表では、1 日の作業と何日かの作業が同じ日に重なったとき、その日は 1 日の作業を描き、何日かの作業はほかの日に普通の高さで描きます（切れ目の角は四角くなります）。同じ日に 1 日の作業が 2 つ以上あるときだけ、その日の中で上下の段に分けます。何日かの作業どうしが重なったとき（指摘が出る置き方）は、どの帯も隠れないよう、上下の段に分けます。

## 8. 品目と、苗数・施肥量

画面の上の「品目」で、品目ごとの設定値と、肥料の銘柄を登録します。どちらもすべてのプランで共通です。

| 設定値 | 使いみち |
|---|---|
| 畝幅、隙間 | 日程の「区画と畝」で品目を選んで畝を足すときの寸法。実際の畝幅と違うと「確認が必要な点」に出る |
| 条数、株間 | 苗数（定植・播種の実績に株間・条数を記録した作付は、実績の値で数える） |
| 窒素（kg/10a）、肥料 | 窒素量と、肥料の量 |
| マルチ | 作付に品目を選んだときの、ひな形の初期値（マルチあり、マルチなし） |
| 定植・播種から収穫開始まで（日）、収穫の日数 | ひな形や並べ直しで入る収穫の日付と、間隔の指摘。その品目の作付にだけ効く |
| 条間、千鳥、品種、メモ | 記録用。計算には使わない |

空の欄は計算に使いません。名前だけの品目も登録できます。

使い方は 2 通りです。

- **畝を足すときに決める**: 日程の「区画と畝」で、畝幅の左の欄から品目を選ぶと、畝幅と隙間が入ります。そのまま「右端に追加」か「＋」で足すと、その品目の作付と、ひな形の作業が付いた畝になります。
- **あとから決める**: 窓の工程の計画で畝を開き、「次の作付を追加」の品目を選んで「作付を追加」を押します。すでにある作付は、作付ごとの品目の欄で選び直します。登録していない品目は、「登録していない品目」のまま名前を入れます。

品目を割り当てた作付には、「区画と畝」の畝の下に苗数と肥料の量が出ます。苗数は、定植・播種の実績に株間・条数を記録していればその値で、なければ品目の設定値で数えます。日程の画面で区画の頭の面積・畝の行を押すと開く「苗と肥料の集計（この区画）」には、選んだ区画の品目ごとの作付の数、面積、苗数と、肥料ごとの合計が出ます。

作業の計画と実績の窓で、肥料と農薬の「1 穴あたり」に量を入れると、対象に選んだ畝の苗数（穴の数）を掛けた量になります。記録の量は使った合計で、1 穴あたりの量も残ります。苗数が分からない畝（品目を登録していない、株間か条数がない）を選んでいると、保存できません。区画で選ぶときは使えません。

品目の名前を変えると、作付の名前も変わります。品目を削除すると、作付には名前だけが残ります。

## 9. 農作業日記

「日記」のタブで、農作業日記を 1 日ずつ書き、読み、探します。日記は圃場ごとではなく共通です。2026-11-07 までは Google ドキュメントに書いていて、その分も移してあります。計画は `docs/actuals-plan.md` の 11.1 にあります。

### 書く

カレンダーで日を選び、「この日の日記を書く」（書いてある日は「修正」）を押します。スマホでは、書いているあいだカレンダーを隠します。

- **本文**: Markdown で書きます。「見出し」を押すと、カーソルの行が見出し（`##`）に、「小見出し」を押すと小見出し（`###`）になります（もう一度押すと元の文に戻ります）。見出しごとに「節」に分かれ、節ごとにタグが付きます。小見出しは節を分けず、見出しの節に入ります（2026-11-10 から。正しくは、節を始めた見出しより深い段の見出しが小見出しです。`###` を一番上に使う日は、`###` ごとの節になります）。小見出しとその下の文や写真は、1 段下げて出します。小見出しを使い始めたら、その見出しの中で親の位置の文には戻りません（Markdown にも戻る書き方はなく、独自の約束も作らない。親の位置に書くことは小見出しより前に書き、後に書くことは「### まとめ」のような小見出しにする）。作物や作業ごとに見出しを付けると、あとで探しやすくなります。空の行は、1 つなら段落の区切り、2 つ以上続けると増えた分だけ空白の行になります。`#`（1 つ）の行は節を区切らないので、`##` から使います。
- **写真**: 写真はスマホのカメラのアプリで撮り、「写真を入れる」でアルバムから選びます（ブラウザーから直接撮ると、Google フォトに残らないことがあります）。短辺 1080 px・品質 85 の JPEG に縮めて上げ、カーソルの位置に入れます。選んですぐ、入れる所に「（写真を上げています…）」の行を置き、上げ終えたら写真に置き換えます。上げているあいだは、ボタンが「上げています 1/3…」に変わって押せなくなり、ヘッダーの下のお知らせにも進み具合が出ます。保存は、上げ終えてからできます。何枚か選ぶと、1 行に並べた表にします。位置情報などの EXIF は外し、撮影日時と元のファイル名だけを DB に残します。もっと大きい写真が要るときは、この 2 つで Google フォトから元の写真を探します。
- **プレビュー**: 入力欄の上の「編集 ｜ プレビュー」のタブで「プレビュー」に切り替えると、保存する前に、見出しや写真が文中に並んだ形を確かめられます。タブの右には「見出し」「小見出し」「写真を入れる」「やめる」「保存」の順にボタンが並びます（「見出し」「小見出し」「写真を入れる」は「編集」のタブのときだけ）。スマホの幅では、タブの下の行に右詰めで並びます。
- **保存**: 「保存」を押すと DB に入り、Claude.ai の日記のコネクタ（`inoo_farm` の `diary-mcp`）からも読めるようになります。書きかけは、打つたびにこの端末に残すので、保存の前に電波が切れたり画面を閉じたりしても、次に開いたときに戻ります。
- **同時に直したとき**: 別の端末で同じ日を先に保存していたら、保存を止めて知らせます。読み込み直してから書き直してください。
- **前の版**: 保存するたびに、前の版が DB（`diary.day_history`）に残ります。画面からは戻せないので、戻すときは DB に直接つないで読みます。どこからも使われなくなった写真は、保存のときに置き場から消します（前の版で使っている写真は残します）。

### 読む、探す

- **日・月**: 「日」か「月」を選び、カレンダーの日を押すと、その日か、その日を含む月の日記を、日付の順に並べます。カレンダーの印は日記のある日で、数字は写真の枚数です。カレンダーの上の年月を押すと、いちばん古い日記の月から今月までのリストが開き、遠い月へすぐ移れます。
- **タグ**: 節ごとに札で出ます。2026-11-08 から、保存のときに語で自動に付けるのをやめ、本人が頼んだときに Claude Code が本文の意味と写真の中身から付けます（計画は docs/actuals-plan.md の 11.1「作物と作業の種類」）。種類は、作物・作業・場所・症状・病害虫・生育段階・話題の 6 つで、種類ごとに札の色が違います。枠だけの札は「対象」（その節が指す作付か区画）です。付けるまでは札がありません。札は推定で、「種類を直す」で 6 つの種類を足したり外したりでき、直した節にだけ「（直した）」と出ます。直した種類は残り、直していない種類は Claude のタグを使います。見出しの名前を変えて保存しても、タグは新しい見出しに引き継ぎます（同じ保存で節を足したり消したりして、どれがどれか決められないときは引き継がず、次にタグを付けるまで札がなくなります）。「Claude のタグに戻す」で、直した内容を外します。写真のタグ（写っているもの、記事向きか記録向きかなど）は、写真を大きく開いたときに出ます。
- **写真の窓**: 写真を押すと大きく開きます。同じ見出しに写真が 2 枚以上あれば、写真の左右の薄い ‹ ›、← → のキー、スマホでは左右にはらう操作で、同じ見出しの写真を行き来します（「2 / 5 枚目」のように出ます）。端まで行くと反対の端に戻ります。
- **札を押す**: 節の札を押すと、そのタグの付いた節を、日の表示と同じ形（本文、写真、札）で並べます。並びは「新しい順」と「古い順」を切り替えられ、古い順にすると、作物の経過を播種から追えます。一覧の中の札を押すと条件に足して絞り（例: ズッキーニ かつ 茎折れ・倒伏、島にんじん かつ 区画1 畝10）、上の札の × で外せます。一度に 20 節まで出し、「続きを出す」で足します。日付を押すと、その日の日記を開きます。一覧の節にも「修正」と「種類を直す」があり、その場で直せます。「修正」は押した節の見出しの下にカーソルを置いて開き、保存してもやめても、一覧の同じ位置に戻ります。対象の札（区画1 畝10 など）で絞ったときは、その作付の作業の記録と、まだ終わっていない計画（予定）も、日付の順に差し挟みます（作付なら区画の作業も、区画なら区画の中の作付の作業も）。どの圃場を開いていても出ます。作業の札（防除など）を重ねると、作業もその種類だけにします。作業の記録を押すと、作業の記録の窓を開きます（その圃場を開いているときだけ。ほかの圃場の記録は、圃場を選び直してから直します）。
- **この作付の日記**: 作付の詳細の頭と、日程の画面の区画の頭に「日記 n 節（最新 M/D）」のボタンを出します。日記の「対象」がその作付（区画なら、区画と区画の中の作付）を指す節の数と、最新の日です。押すと日記の画面で、その対象の札で絞った一覧を古い順に開き、作業の記録と予定も差し挟みます。ブラウザーの「戻る」で、元の画面に戻ります。日記がないときと、ほかのプランを開いているときは出しません（日記の対象は実際に使うプランの作付を指すため）。
- **探す**: 検索ワードを入れて「探す」を押すと、すべての語を含む日を、新しい日から 200 日まで出します。空白で区切ると、すべてを含む日だけを出します。全角と半角、大文字と小文字の違いは見ません。

PC では、日記の画面をブラウザーの高さに収めます。カレンダーは動かず、日記が枠に収まらない日だけ、日記の枠の中にスクロールバーが出ます。

日記の保存は、「元に戻す」の対象外です。

## 10. 変更の履歴

画面の上の「履歴」で開きます。計画を変えるたびに、何を変えたかが自動で 1 行ずつ残ります。

- **日ごとに並ぶ**: 新しい日が上で、日の中も新しい変更が上です。
- **番号**: 全体の通し番号です（#41 など）。プランをまたいでも重なりません。行をまとめたり消したりしても、番号は詰めません。
- **プラン**: 記録はプランから独立していて、どのプランでの変更かが行に出ます。品目、肥料、縮尺など、プランによらない変更は「共通」と出ます。
- **圃場**: アプリの開発日誌なので、すべての圃場の記録が並びます。圃場が 2 つ以上あるときは、「圃場の名前 / プラン」と出ます。
- **文**: その時点の名前で書きます。あとで区画や品目の名前を変えても、過去の記録の文は変わりません。値を変えた操作には、変える前と後の値が付きます。
- **まとめ**: 同じ圃場で、同じ相手への同じ操作が 30 分のうちに続いたときは、1 行にまとめ、最初の「前」の値と最後の「後」の値を残します（畝を何度も動かしたときなど）。圃場とプランの作成・コピー・名前の変更・削除は、相手の圃場やプランごとに行を分けるので、別々のプランの操作が 1 行にまとまることはありません。
- **メモ**: 日ごとに 1 つ、なぜそうしたかを書けます。すべての圃場で共通です。メモに `#41` のように番号を書くと、その行へ飛ぶボタンが出ます。
- **行をクリック**: その区画、畝、作付を開きます。圃場とプランの作成などの行は、その圃場とプランを開きます（ほかの圃場のものでも開きます）。もうないものと、いま開いていない圃場やプランの区画・畝・作付は開けません。

記録が残るのは、この仕組みを入れたあとの変更だけです。記録の行は、画面からは消せません。

### アプリの更新

アプリそのものに加えた変更は、`app/updates.json` に書きます。「履歴」の画面では、「アプリ」の札と、A の付いた番号（A12 など）で、同じ日の欄に並びます。メモからは `A12` のように触れられます。

| 項目 | 内容 |
|---|---|
| `no` | 通し番号。足すたびに 1 ずつ増やす |
| `date` | 公開した日 |
| `title` | 何ができるようになったか |
| `body` | 使う人に向けた説明 |
| `reason` | なぜ変えたか。きっかけになった困りごと |

push のたびに、できるようになったことごとに 1 件ずつ足します。
このファイルは公開されるので、圃場の場所、面積、実際の品目や時期は書きません。

画面は、アプリのファイルを一式ブラウザーに取っておき（`app/sw.js`）、起動のときはそこから出します。新しい版は画面が出たあとで取り、ヘッダーの下に出る「アプリの新しい版があります」の「読み込み直す」を押すか、次に開いたときに切り替わります。

保存や操作の結果は、ヘッダーの下に重ねて出るお知らせで知らせます（`app/toast.js`）。ヘッダーや画面の形は変わりません。

- **操作の結果**（実績を入力しました、など）: 2 秒で消えます。
- **保存**: 「保存しました」は出しません。保存に 1 秒以上かかるときだけ「保存中…」を出します。
- **進み具合**（画像を保存中… 45% など）: 終わるまで出ています。
- **失敗**（保存に失敗しました、日記を読み込めませんでした、など）: 自然には消えません。「詳しく」で誤りの内容を窓に出し、「×」で閉じます。保存の失敗は、あわせて窓でも知らせます。

ただし、DB の形が古い版の画面では正しく書けない形に変わったときは、古い版の画面は起動のときにデータを出す前に止まり、新しい版を取って読み込み直します。新しい版がまだ公開されていなければ、そう知らせて止まったままにします。どの版から使えるかは、DB の `field.app_compat` に持たせます。DB の形を変えるときの手順は `docs/implementation-rules.md` にあります。

### 元に戻す、やり直す

どの画面でも、Ctrl+Z で直前の操作を元に戻し、Ctrl+Y（または Ctrl+Shift+Z）でやり直せます。画面の右上のボタンでも同じです。

- **対象**: いまのプランの区域、区画、畝、作付、作業と、圃場の外形、品目、肥料、作業の種類の目安、圃場の実績。
- **1 回ぶん**: ドラッグは離すまでが 1 回、ボタンは 1 回押すごとに 1 回です。文字を打っているあいだは、入力欄の「元に戻す」が働きます。
- **回数**: 50 回ぶんまで。画面を開き直すと、履歴はなくなります。
- **戻せない操作**: 日記の保存と、日記の作物・作業の種類の直し（前の版は DB に残ります。9 章）、プランの切り替え・作成・コピー・削除・名前の変更、「実際に使うプラン」の切り替え、圃場の切り替え・作成・削除・名前の変更、縮尺と向きの合わせ直し、下絵の読み込みと、下絵だけの縮尺・向き・位置の変更、気象の設定、メモ、別のプランを開いているときの、実際に使うプランの計画の変更。プランの切り替えなどと、縮尺・向きの合わせ直しをすると、それまでの履歴は空になります。
- **履歴**: 元に戻したこと、やり直したことも、変更の履歴に 1 行残ります。戻す前の行は消えません。

### PDF 出力

圃場図の右上と、「工程表」の右上に「PDF出力」があります。押すとブラウザーの印刷の画面が開くので、出力先（送信先）で「PDF に保存」を選びます。紙は A4 です。保存するファイル名は、初めから「圃場図」「工程表」になります。

- **圃場図**: 下絵の写真は入りません。1 枚目は全体で、範囲は、圃場の外形（離れた部分もすべて）がちょうど入る四角形に 3% の余白を足したもの、向きは画面と同じ（上が北）です。全体が横長なら紙を横に、縦長なら縦に使い、すべての紙で同じ向きです。外形が離れた部分に分かれているときは、続けて、部分ごとに 1 枚ずつ、その部分を紙いっぱいに描いた紙が出ます。選択の印は出ず、表示日の区画と畝が出ます。圃場の外形と有効圃場の各辺の長さが、辺の外側に入ります（画面の圃場図には出ません）。左下に縮尺の線が入ります。
- **工程表**: 表示期間によらず、作業のある範囲の全体を、横向きの紙の幅に収めて出します。日程の画面では、選んだ区画だけを出します（題に区画の名前が入ります）。行が多いときは、次の紙に続きます。

## 11. MCP サーバー（Claude.ai から計画と実績を読む）

計画と作業の実績を、Claude.ai のコネクタから読むためのサーバーです。読むだけで、書き換えはできません。

| 機能 | 内容 |
|---|---|
| `list_fields` | 圃場の一覧と、それぞれの面積、プラン、実際に使うプラン、最後に変更のあった日、記録の数 |
| `list_plans` | 1 つの圃場のプランの一覧と、それぞれの規模、最後に変更のあった日 |
| `get_plan` | 1 つのプランの全体。区域、耕起対象区画、畝、作付（品目、苗数、肥料の量、作業の日付）、集計、日程の無理の指摘 |
| `get_schedule` | 期間を決めた作業の一覧。同じ日の同じ作業は、場所をまとめる |
| `get_changes` | 日ごとの、計画の変更（# の番号）、メモ、アプリの更新（A の番号） |
| `get_crops` | 品目の設定値と、肥料の銘柄 |
| `get_records` | 作業の実績（作業をした日と、何日かかかった作業の終えた日、対象の畝、仕様、資材、メモ、つながる計画の作業）と、取りやめた計画の作業。期間、品目、作業、場所で絞れる |
| `get_pesticide_usage` | 実際に使うプランの作付ごとの、農薬の使用回数（本剤ごと、有効成分ごと）と上限、使用時期の基準を満たす最初の収穫日、作用機構分類（`rac`）。農薬の使用基準（FAMIC）を使う部分で、Supabase の秘密の値 `FIELD_FAMIC` を `false` にすると外れる。`get_records` の農薬に付く `rac` も、このとき外れる |

`list_fields` と `get_crops` のほかは、毎回 `field` で圃場を選びます（名前の一部でもよい）。
品目と肥料、日ごとのメモ、アプリの更新は、すべての圃場で共通です。

サーバーは、DB にある内容をすべて返します。区域の名前、面積、時期も含みます。
記事にするときに出さない情報は、Claude.ai の側で指定します。

### コネクタ URL の作り方

コネクタの URL は、関数の URL の末尾に「合言葉」を付けたものです。合言葉が違う呼び出しには、サーバーは何も返しません。

```
https://byhthaiwbutqstrqbwwc.supabase.co/functions/v1/field-mcp/<合言葉>
```

合言葉を作って Supabase に登録し、URL を表示します。PowerShell で、このリポジトリのフォルダーから実行します。

```powershell
$t = python -c "import secrets; print(secrets.token_urlsafe(32))"
bun x supabase secrets set "FIELD_MCP_TOKEN=$t" --remote=byhthaiwbutqstrqbwwc
"https://byhthaiwbutqstrqbwwc.supabase.co/functions/v1/field-mcp/$t"
```

3 行目が表示した URL を控えます。合言葉はあとから取り出せないので、控え忘れたら作り直してください。

### Claude.ai に登録する

1. Claude.ai の「設定 > コネクタ」で、カスタムコネクタを追加します。
2. 上で表示された URL を入力します。
3. 認証は「No sign-in」を選びます。

### URL の扱い

**URL そのものが鍵です。** 人に見せたり、公開の場所や会話に貼ったりしないでください。
漏れた疑いがあるときは、「コネクタ URL の作り方」をもう一度実行します。合言葉が入れ替わり、古い URL は使えなくなります。

呼び出しは `field.mcp_access_log` に残ります。合言葉が違う呼び出し（`authorized` が false）が続いていないかを、ここで確かめられます。

### サーバーを配備する

画面と同じ計算をするために、`app/` の部品（`geometry.js`、`schedule.js`、`crops.js`、`updates.json`）の写しを、サーバーのフォルダーの `lib/` に置いています。
`app/` の側か `supabase/functions/field-mcp/` を変えたら、写してから、テストして配備します。合言葉は変わらないので、コネクタの登録はそのまま使えます。

```powershell
node scripts/sync-mcp-lib.mjs
node --test "tests/*.test.mjs"
bun x supabase functions deploy field-mcp --remote=byhthaiwbutqstrqbwwc --no-verify-jwt
```

配備の前に、本番のプロジェクトに配備してよいかを確かめられます（Supabase CLI 3.0 から）。`agri_db (byhthaiwbutqstrqbwwc)` と出ていれば、Yes を選びます。確かめずに配備するときは `--yes` を付けます。

写しが古いままだと、テストが失敗します。

アプリの更新の一覧（`updates.json`）だけは、サーバーが呼ばれるたびに、公開しているアプリ（`https://yonhon.github.io/field_plan/updates.json`）から読みます。そのため、一覧を足したときは、アプリを公開するだけで Claude.ai にも届きます（GitHub Pages が最大 10 分ためておくので、少し遅れることがあります）。読めないときや、公開しているものが配備したときの写しより短いときは、写しを使います。

## 12. 手元での確認

```
python -m http.server 8765 --directory app
```

```
node --test "tests/*.test.mjs"
```

```
node --test "tests/e2e/*.test.mjs"
```
