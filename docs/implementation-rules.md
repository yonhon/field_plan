# 実装のきまり

処理を書くとき、直すときに守るきまりです。画面の見た目のきまりは `docs/design-rules.md` にあります。

## 待つこと

- **確認の窓や保存を待つ関数は、呼び出す側も `await` する。** `confirmAction` や `confirmDelete` は、利用者が答えるまで終わらない。呼び出したあとの処理は、待たないと答えの前に走る。
- **同期の関数を async に変えたら、呼び出す側をすべて直す。** 呼び出す関数が Promise を返さないと、その先は待てない。包むだけの関数でも `return` する。
- **図は、データを変え終えてから描き直す。** `render` は圃場図と右の欄だけを描く。日程の画面を変えたら `renderSchedule` も呼ぶ。

## 保存の順序

- **親の行を、子の行より先に送る。** 区域 → 区画 → 畝 → 作付 → 作業の順に外部キーがあり、子が先に届くと 23503 で断られる。毎回は起きないので、動かして見ただけでは気づけない。
- **DB への書き込みは `state.store` を通す。** `inOrder` が呼んだ順に 1 つずつ送るので、親を先に呼べば順序は守られる。
- **`queueSave` は、すぐには送らない。** 600 ms あとに送る。`queueSave` した行を親にする行を保存するときは、先に `sendPendingSaves` を待つ。
- **画面の中の値が変わったことは、保存が終わったことを意味しない。** 保存のあとに続く処理は、その完了を待つ。
- **DB への書き込みの関数を足したら、`QUEUED_WRITES` にも足す。** 送る順序と、操作の ID（`op_id`）は、ここで決まる。

## 失敗の知らせ方

- **保存の失敗は、窓で知らせる。** ヘッダーの下のお知らせは、ほかの保存が終わると置き換わったり消えたりする。`persist` と `run` は失敗すると `notifySaveFailed` を呼ぶので、これらを通して保存する。
- **保存の状態の文字は `setStatus` で出す。** 送り残しがあるあいだは「保存しました」と書かず、もう一度送る。書いた文は、目に見えない記録の欄（`#saveStatus`）に入り、`app/toast.js` がヘッダーの下のお知らせに出す。失敗は「…に失敗しました: 誤りの内容」「…ませんでした: 誤りの内容」の形で書く（この形のものだけが、閉じるまで残るお知らせになる）。
- **失敗を捨てない。** `catch` したら、利用者に見える形で知らせる。

## 元に戻す

- **新しい操作を足すときは、元に戻せるか確かめる。** いまの仕組みは、`history.js` の写しに入っているデータだけを戻す。写しの外のデータを変える操作は、戻らないだけでなく、「元に戻す」が前の別の操作を戻してしまう。
- **戻せない操作は、README の「元に戻す、やり直す」に書く。** 監査ログと `op_id` で戻す仕組みへ移るまでのきまり。
- **保存を待ってから変わるデータは、変わった時点で `noteChange` を呼ぶ。** 操作から時間がたつと、次の操作と 1 回ぶんになる。

## DB の形を変える、部品を足す

画面は、アプリのファイルを一式ブラウザーに取っておき（`app/sw.js`）、起動のときはそこから出す。新しい版に切り替わるのは、お知らせの「読み込み直す」を押すか、次に開いたとき。そのため、公開してからしばらくは、古い版の画面が DB に書く。

- **古い版の画面では正しく書けない形に DB を変えるときは、古い版を止める。** 列の名前を変える、必須の列を足す、書き込みの決まりを変える、などのとき。次の順に行う。
  1. `app/store.js` の `APP_VERSION` を 1 つ上げ、DB の変更に合わせた画面を公開する。
  2. 開いたままの画面を閉じておく。起動のときにしか確かめないので、開いたままの画面は止まらない。
  3. 公開を待ってから、DB を変える SQL の中で、`field.app_compat` の `min_version` を同じ値に上げる（`update field.app_compat set min_version = 2;`）。

  `min_version` より古い画面は、起動のとき、データを出す前に止まって、新しい版を読み込み直す。順序を逆にすると、新しい版がまだないので止まったままになる。
- **古い版の画面でも壊れない変え方ができるなら、そうする。** 列を足すだけなら、古い版は新しい列を知らないまま動ける。先に列を足し、両方の版が動くようにしてから、古い列を消す。
- **JS の部品（ファイル）を足したら、`app/sw.js` の `FILES` と、`app/index.html` の `parts` の両方に足す。** 漏れると、その部品だけが一式から外れ、古い版と新しい版が混ざる。`tests/sw.test.mjs` が漏れを確かめる。
- **画面が読むファイル（アイコンなど）を足したときも、`FILES` に足す。**

## 画面を描く

画面は、入れ物の中身を HTML の文字列で丸ごと作り直して描く。作り直すと、スクロールの位置とカーソルが失われるので、`app/draw.js` の `draw` を通して描く。`draw` は、作り直す前に、触っていた所の高さ、スクロールの位置、カーソルのある欄を覚え、作り直したあとに戻す。

将来、違う所だけを書き換える仕組み（idiomorph など）に替えるときは、`draw` の中身だけを替える。替えると、作り直さずに前の要素を残して使うようになる。そのときに直す所が出ないよう、次のきまりを守る。

- **中身を入れ替えるときは `draw(入れ物, html)` を使う。`innerHTML`、`outerHTML`、`insertAdjacentHTML` を直接使わない。** 直接使うと、スクロールの位置とカーソルが失われる。`tests/draw.test.mjs` が確かめる。中身を空にするだけなら `replaceChildren()` でよい。
- **画面の状態は、データに持つ。描いた要素から読み戻さない。** チェック、選んだもの、開いている欄、入れかけの文字などは、操作のたびにデータ（`draft` など）へ入れ、描くときはデータから HTML を作る。要素に残った状態は、作り直すと消え、前の要素を残す仕組みでは前の値が残る。どちらでも同じに見えるのは、データから描いたときだけ。
- **HTML で書けない状態（`indeterminate` など）は、描くたびに、データから付け直す。** `draw` のすぐあとに付ける。前に付けた値が残っていることを当てにしない。
- **操作の処理は、入れ物か、その外の要素に付ける。描いた中身の要素には付けない。** 中身の要素に付けると、作り直す仕組みでは描くたびに消え、前の要素を残す仕組みでは描くたびに重なる。入れ物に付け、`event.target.closest(…)` でどの要素かを見分ける（`crops-view.js` の `bind`）。
- **描いた中身の要素を、描き直しのあとまで持ち続けない。** 描き直したあとは、`querySelector` で探し直す。作り直すと前の要素は画面から外れ、前の要素を残す仕組みでは同じ要素が別の中身になる。
- **入力欄、ボタン、行には、`data-*` か `id` で、どれかが分かる印を付ける。** `draw` は、この印で、作り直したあとの同じ要素を探す（行の `data-id` と欄の `data-field` を合わせて、「どの行のどの欄」かを決める）。印のない要素には、カーソルを戻せない。違う所だけを書き換える仕組みも、この印で同じ要素を見分ける。
- **作り直したことで、元に戻ることを当てにしない。** 入れかけの文字を消す、スクロールをいちばん上にする、などは、その処理を書く。前の要素を残す仕組みでは、作り直さないので戻らない。窓を閉じたあとに中身を空にする（`log-view.js`）のも、このため。
- **文字を打つたびに（`input` の知らせで）、その欄を含む入れ物を描き直さない。** 日本語の変換の途中で作り直すと、変換が切れる。打つたびに変える所（検索の結果など）は、別の入れ物にして、そこだけを描く。

- **SVG の文字の一部だけを押せるようにするときは、`tspan` に分けず、押した位置から文字を求める。** WebKit（iPad、iPhone の Safari と Chrome）では、`tspan` に分けると、`dominant-baseline` が効かずにその部分だけ高さがずれ、`pointer-events` も効かず下の図形が押される。PC の Chrome ではどちらも起きないので、通しテストでは気づけない。圃場図の品目名は、文字を 1 つのまま、`getExtentOfChar` で押した位置が品目名の文字の範囲かを求めている（`app.js` の `mapLabelAt`）。文字が図形からはみ出すときは、図形をすべて描いたあとに文字を描く（先に描くと、隣の図形に隠れる）。

## 確かめ方

- **操作の流れを変えたら、ブラウザーの通しテストを動かす。** 計算のテストは、画面の操作のバグを見つけられない。主な操作を足したら、`tests/e2e/` にテストを足す。
- **保存に関わる変更は、`?local=1&strict=1` で動かす。** 親の表ほど保存を遅くし、親のない行を断る。ふつうの `?local=1` は保存がすぐ終わるので、順序の誤りが出ない。
