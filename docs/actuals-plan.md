# 実績の記録と、農作業日記との突き合わせ（計画）

README の「作る順番」の 5 番目の計画です。まだ実装していません。
決まっていない点は、最後の「決めること」にまとめています。

## 1. ねらい

- 計画した作業に、実際に行った日を記録する。
- 計画と実績のずれを見て、後ろの計画を直せるようにする。
- 農作業日記（`inoo_farm` の `diary` スキーマ）の記録を、作業の横で読めるようにする。

## 2. 前提

日記にあるのは、日付、作物、作業の種類、本文、写真です。区画や畝の情報はありません。
そのため、日記から「どの畝の作業を、いつ行ったか」を自動で決めることはできません。

この計画では、次の役割分担にします。

| 記録 | 役割 |
|---|---|
| 計画の画面（このアプリ） | 実績の日を入れる場所。区画、畝、作付ごとに、作業 1 件ずつ |
| 農作業日記 | 裏付けと詳細。作業の横に、近い日の日記を出す |

## 3. 作るもの

### 3.1 実績の入力

作業 1 件ごとに、実施日（開始と終了）を入れます。`field.works` には `actual_start` と `actual_end` の列がすでにあるので、テーブルの変更はありません。

- **スマホから入れられるようにする**: 圃場で入れる場面が主になります。スマホはいま閲覧だけなので、この機能で初めて書き込みができるようになります。
- **「今週やること」に完了ボタン**: 押すと、今日の日付が実績に入ります。日付はあとから直せます。同じ日の同じ作業を畝ごとにまとめた行は、まとめて完了にできます。
- **「作業の計画」の表に実績の列**: PC では、表の中で開始日と終了日を入れます。
- **期間のある作業**: 太陽熱消毒や収穫は、「始めた」と「終わった」を別々に入れます。

### 3.2 計画と実績の見え方

| 場所 | 表示 |
|---|---|
| 工程表 | 計画の帯の下に、実績の細い帯を重ねる |
| 今週やること | 完了した作業は薄くする。予定日を過ぎて未完了の作業を、「遅れている作業」として上に出す |
| 区画と畝の図 | 作業の名前の横に、済みの印を付ける |

### 3.3 遅れへの対応

- **計画は自動では動かさない**: 勝手に書き換えると、元の計画が分からなくなるためです。
- **「実績に合わせて後ろを並べ直す」**: 区画や作付ごとに、実績の終了日を起点にして、残りの作業を目安の日数で並べ直します。いまの並べ直しの計算（`app/schedule.js`）を使います。
- **指摘**: 実績の入った作業は、計画の日ではなく実績の日で、前後の間隔を見ます。

### 3.4 日記との突き合わせ

- **対応の表**: 計画の作業の種類と品目を、日記の作業の種類と作物に対応させます。

  | 計画の作業の種類 | 日記の作業の種類 |
  |---|---|
  | 畝立て | 畝立て・耕うん |
  | ロータリー、すき込み | 畝立て・耕うん |
  | マルチ張り | マルチ |
  | 定植・播種 | 定植、播種 |
  | 堆肥・石灰・基肥 | 施肥 |
  | 収穫 | 収穫、出荷 |
  | 残渣処理 | 片付け |
  | 心土破砕、太陽熱消毒、緑肥 | 対応する種類なし（日付だけで探す） |

- **作業の横に日記を出す**: 実績の日（なければ計画の日）の前後数日で、作業の種類と作物が合う日記の節を一覧にします。見出し、本文の冒頭、写真の枚数を出し、開くと全文を読めます。
- **日記の日付を実績に入れる補助**: 合う日記があり、実績が空の作業には、「この日記の日付を実績に入れる」を出します。押したときだけ入ります。

### 3.5 日記を読む仕組み

日記は、ほかの方の氏名や連絡先を含むので、画面から直接は読めない場所に置いてあります。計画の画面から読むには、出入口を新しく作る必要があります。

| 案 | 内容 | 評価 |
|---|---|---|
| A | 日記の DB に、ログインした本人だけが呼べる読み取り専用の関数を 1 つ足す。返すのは日記の節だけで、LINE のメッセージは返さない | 変更が小さい。こちらを勧める |
| B | 日記用のサーバー（`diary-mcp`）に、画面向けの窓口を足す | 合言葉の管理が増える |

どちらも `inoo_farm` の側の変更です。

## 4. 作る順番

1. **実績の入力と表示**（3.1、3.2）: 日記がなくても、単独で役に立ちます。圃場での作業が始まるまでに必要なのは、ここまでです。
2. **遅れへの対応**（3.3）
3. **日記との突き合わせ**（3.4、3.5）: この圃場の日記がたまってから効いてくるので、最後にします。

## 5. 決めること

| 番号 | 決めること | 選択肢と影響 |
|---|---|---|
| 1 | 実績の単位 | 実施日（開始と終了）だけなら、テーブルの変更なしで作れる。作業時間、人数、資材の量、収穫量まで記録するなら、テーブルを足す |
| 2 | スマホでの書き込みの範囲 | 完了ボタンと日付の修正だけにするか。メモや写真も入れられるようにするか |
| 3 | 日記の書き方 | この圃場の作業も、同じ日記に書くか。書くなら、見出しに区画や畝の名前を入れると、突き合わせの精度が上がる |
| 4 | 日記を読む仕組み | 案 A でよいか |
| 5 | 日記にない作業の種類 | 心土破砕、太陽熱消毒、緑肥、残渣処理を、日記の側の作業の種類にも足すか。足すなら `inoo_farm` の `config/tags.json` を変える |

1 と 2 で、作る量が大きく変わります。
最小の形（実施日だけ。スマホは完了ボタンと日付の修正）なら、テーブルの変更なしで「作る順番」の 1 まで作れます。
